SUMMARY
-------
The study's best recipe (server pretraining, then FedAvg over day-clients
with own-day noise) now runs as a real federated system: one Flower server
process and ten independent client processes that exchange only model
weights over gRPC, each client holding only its own data. The system is
VALIDATED. It produces bit-identical models to the simulator that produced
the study's results, including over full 200-round runs. The study's
conclusions (report 24) therefore transfer to it unchanged.

2. PERFORMANCE
  A full 200-round run with 10 clients took 281-293 s on one RTX 4060.
  That is faster than the simulator's effective 367 s, because the client
  processes share the GPU in parallel. Traffic is 3.45 GB per run
  (17.3 MB per round).

3. DEFECTS FOUND AND FIXED (all before the validation runs; details in
   report 26)
  - folder-creation clash;
  - object arrays in provisioning v1;
  - a server hang when clients never connected (now a watchdog);
  - a design flaw that would have broken exact resume (now per-round state
    with rollback);
  - RNG state restored to the wrong device.
  T5 note: my first theoretical byte count wrongly added an initial
  parameter download. Flower sends the parameters inside each round's fit
  instruction. The corrected theory matches the measurement within 1.1 %.

4. WHAT THIS DOES AND DOES NOT ESTABLISH
  Established: the deployed protocol (separate processes, network
  transport, per-site data isolation, strict synchronous FedAvg, exact
  restart) computes exactly the models analysed in the study. The study's
  answers apply to it:
    - federated training is equivalent to central within the margins;
    - server pretraining helps on lobe structure;
    - no extra day-nuisance encoding.
  Not established (listed in fl_system/README.md):
    - operation across real separate machines (different GPUs or libraries
      would break bit-identity; equivalence must be re-checked as in T2);
    - TLS, secure aggregation and differential privacy (not configured; the
      nuisance gate is not a privacy guarantee);
    - long-term API support: the long-lived Flower API used here is
      deprecated, and the migration path is documented;
    - only fold 0 was provisioned and tested;
    - vehicle-level claims (no labels), as in the study.
