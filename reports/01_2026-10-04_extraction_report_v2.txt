--------------------------------------------------------------------------------
1. OVERVIEW: FROM MAGNETIC FIELD TO FEATURE VECTOR
--------------------------------------------------------------------------------

A vehicle is a large mass of ferromagnetic steel. As it passes the sensor it
distorts the Earth's magnetic field locally. A spintronic TMR (tunnel
magneto-resistance) sensor turns that field change into a resistance change,
which the logger digitises at ~2.4 kHz. A passing car therefore shows up as a
slow (energy < 2.5 Hz), usually bipolar or tripolar excursion lasting 2-12 s,
sitting on a drifting baseline and buried under 50 Hz mains interference
(about 1.4k counts).

The extraction pipeline turns 340 hours of raw stream (35 GB, 29 417 binary
chunks, 4 recording runs, 14 days) into a table of discrete vehicle events:

   raw .bsd files (uint32 codes + uint64 ticks)
      |  [A] decode 24-bit codes, rebuild exact ADC sample index ("slots")
      v
   continuous stream per run, ~2416 Hz, dropouts located
      |
      +--> [C] DETECTION path: FIR 10 Hz + decimate to ~50 Hz, baseline,
      |        robust sigma, high-pass, hysteresis on envelope -> events
      |        (onset, offset, energy centroid, SNR)
      |
      +--> [B] FEATURE path: 50 Hz mains regression -> Butterworth LP 8 Hz
      |        -> polyphase resample to ~50 Hz -> two-pass 20 s median
      |        baseline subtracted
      v
   [E] for every event: 21 s window (1050 samples) centred on the centroid,
       onset/offset mask, dropout/repair mask, metadata
      |
      v
   [D] 19 morphology scalars, computed twice:
       m_*  on the full 21 s window
       m8_* on the central ~8 s (402 samples)   <- recommended set

Final output: 15 260 events (4 375 with SNR >= 20, the recommended training
tier), each with a waveform, two masks, 38 morphology features and 32
metadata fields.

The letters A-E refer to the research workstreams that designed and
validated each stage (research/extraction/{A_integrity, B_signal,
C_detection, D_features, E_pipeline}). The validated modules from A-D are
copied verbatim into extraction/_vendor/ and carry a provenance header with
the sha256 of the original.

2. THE PHYSICAL SIGNAL AND THE RAW DATASET
--------------------------------------------------------------------------------

Dataset folder:
  "Spintronic Sensor Dataset for Vehicle Detection and Car Model Recognition
   (14 Days, Unlabeled with Timestamps)/"

Four runs (one folder each):
  Run 20250204 15h24m13s - 20250211 16h30m16s   (169.2 h, includes a weekend)
  Run 20250212 14h41m50s - 20250214 16h30m31s   ( 49.8 h)
  Run 20250218 11h12m41s - 20250220 14h40m28s   ( 51.4 h)
  Run 20250224 14h55m20s - 20250227 14h38m27s   ( 69.6 h)

Hardware config ("Configuration - Hardware.cfg"):
  Sampling Rate :: 2400    Gain :: 8    DAC Mode :: DIFFERENTIAL
  Data Points per file :: 100000      Site: "INL GATE - Much After Barrier"

Each chunk (~41.4 s) is a pair of files:
  "S0C0 BIN Values - NNNNNN Start@... Stop@....bsd"
      little-endian uint32, 100 000 samples = 400 000 bytes.
      ONLY THE LOW 24 BITS ARE USED; the top byte is always 0.
      This is a 24-bit ADC code. Observed range is 11.19M-11.97M counts,
      far from both rails, so there is no clipping.
  "S0C0 BIN Time - ...bsd"
      little-endian uint64, one device-timer tick per sample.

Facts established by workstream A (integrity) that the code relies on:
  * The Time values are device ticks, NOT microseconds. Against the PC wall
    clock the tick rate is off by +1 % to +5 % and drifts during the day.
    Ticks are used only to order samples and to find dropouts.
  * The true sample rate is fs ~= 2416 Hz, not the configured 2400. It ranges
    2407-2421 Hz per chunk and is stored per chunk as `fs_local` in A's chunk
    index (research/extraction/A_integrity/chunk_index.parquet).
  * There are 188k dropouts, mostly bursts of ~105-106 lost samples (one
    ~44.5 ms timer gap), plus some 1-4-sample losses. They are concentrated
    in run 0204 from Feb 6 onwards (~1 % of samples).
  * No files are missing. Total: 340 h.

Facts established by workstream B (signal):
  * Vehicle energy is below 2.5 Hz; events are mostly bipolar and 2-12 s long.
  * 50 Hz mains plus harmonics is about 1.4k counts.
  * The baseline wanders strongly. It must be SUBTRACTED, never divided out
    (dividing by the "DC" is pointless because it varies only 0.975-1.009).

--------------------------------------------------------------------------------
5. STEP-BY-STEP PIPELINE
--------------------------------------------------------------------------------

5.1 Reading the binary files  (_vendor/bsd_io.py, blockio.py)
---------------------------------------------------------------
  values = np.fromfile(values_path, '<u4') & 0xFFFFFF    # 24-bit ADC code
  ticks  = np.fromfile(time_path,   '<u8')

  Slot reconstruction (bsd_io.slots_from_timestamps, the "clean-anchor"
  estimator):
    - A tick delta greater than 1.5 x the median delta marks a gap.
    - Between two "clean" samples a < c:
          slot(c) - slot(a) = max(c - a, rint((t_c - t_a) / base_dt))
      so the number of lost samples is recovered exactly.
    - The first stamp after a dropout is late by 0-0.9 slot (mean 0.24),
      and the estimator corrects for this.
    Result: an integer ADC slot index for every sample. Time is then
    slot / fs_local, never ticks / 1e6.

  chunk_index() reads A's validated index: per chunk it stores the paths,
  run, slot_start (run-global), interchunk_slots, fs_local and wall_start
  (from a piecewise-linear fit to the PC clock, +-0.35 s).

  SlotClock maps any run-global slot to its chunk, its fs_local and its wall
  time:
      wall = wall_start(chunk) + (slot - slot_start(chunk)) / fs_local(chunk)
  fs_eff_mean(a, b) returns the slot-weighted mean of fs_local*25/1208 over
  a window (needed for the 1.3 % of windows that straddle two chunks with
  different fs_local).

5.2 Stitching chunks into blocks  (pipeline.make_blocks, blockio.load_block)
----------------------------------------------------------------------------
  - Each run is cut into blocks of CORE_CHUNKS = 60 chunks (~41 min).
  - Each block also loads CONTEXT_CHUNKS = 3 chunks (124 s) on each side,
    because the detector's baselines need >= 60 s of context.
  - load_block concatenates the chunks and asserts that every chunk starts
    exactly at prev_last_slot + interchunk_slots, so no slot is guessed.
  - A block keeps only events whose centroid falls inside its core. Events
    that straddle chunk boundaries are therefore handled naturally.

5.3 Event detection: HYST-BP  (_vendor/detector.py, pipeline.detect_block)
-------------------------------------------------------------------------
  Called as  detect_stream(v, slot - slot[0])  so that dropout
  re-insertion uses A's exact slots.

  a) Front end: missing slots are re-inserted by linear interpolation; a
     481-tap Hamming FIR (10 Hz cut-off, >50 dB above ~27 Hz, so it removes
     mains and harmonics) is applied, then decimation by 48: 2416/48 = 50.33 Hz.
     Output samples whose FIR support touches a dropout are discarded and
     bridged at 50 Hz (flag: has_dropout).
  b) A 0.5 s median filter on the detection channel removes a periodic
     0.1-0.15 s impulsive "pulser" interference.
  c) Baseline: two-pass rolling median (60 s) of 1 s block medians.
     Pass 2 masks samples flagged by pass 1 (|z| > 4 sigma, dilated +-8 s)
     so that long or clustered events do not pull the baseline.
  d) Noise: rolling 5 min robust sigma (1.4826 x MAD).
  e) The detection channel is high-passed (4 s moving-average subtraction,
     ~0.1 Hz) and re-normalised by its own rolling robust sigma.
  f) Envelope: 0.2 s moving RMS of z/sigma.
     Hysteresis: a segment starts above 5 sigma and is extended while above
     2 sigma. Gaps < 1 s are merged. Segments are split at deep valleys
     (< 0.2 x the smaller neighbouring peak, peaks >= 1 s apart).
     Segments < 0.3 s are dropped.
  g) For each segment it reports: onset, offset, peak_t, peak_z (signed
     counts), snr = |peak z| / sigma, the energy centroid
     centroid_t = sum(t z^2) / sum(z^2), the 1 %/99 % energy extent,
     has_dropout, and n_neighbours_in_window (other events overlapping the
     21 s window).
  Why HYST-BP: on the holdout run it beat fair fixed windows by
  dF1 = +0.16, and the ranking held under independent injection templates.
  The old "DC-relative fixed windows" scored F1 = 0.006.

  pipeline.detect_block converts all event times back to run-global slots:
      slot_x = slot[0] + x * 2416

5.4 Feature path  (featpath.feature_path; B's chain from _vendor/preproc.py)
---------------------------------------------------------------------------
  This is a separate, gentler path that produces the waveform the features
  are measured on. (The detection path is tuned to find events; this path
  is tuned to preserve their shape.)

  1. Split and fill: v is centred on its median. Dropouts of 1-4 samples are
     linearly filled. Dropouts of >= 5 samples split the stream into
     segments. Segments < 0.5 s are discarded (masked).
  2. Mains removal (preproc.remove_mains), per segment:
       - 10 s blocks with 50 % overlap;
       - in each block, f0 is re-estimated by zero-padded FFT peak search
         in 49-51 Hz;
       - least squares fit of [1, t, t^2, t^3, cos/sin(2 pi k f0 t), k=1..20],
         and only the harmonic part is subtracted (the polynomial absorbs
         the slow vehicle/baseline so it is not fitted away);
       - overlapping blocks are cross-faded with Hann weights, so there are
         no steps at block edges.
  3. Low-pass: 4th-order Butterworth at 8 Hz, zero-phase (sosfiltfilt),
     even padding. It is designed at the segment's TRUE fs_local, not at 2416.
  4. Resampling by 25/1208 (2416 x 25/1208 = 50 Hz), done "phase-exact" by
     resample_to_grid(): the same Kaiser(5) polyphase filter as
     scipy.signal.resample_poly, applied with upfirdn and offset so that
     output sample j lands exactly at run-global slot j x 1208/25 for every
     segment. The effective output rate is fs_eff = fs_local x 25/1208, which
     is 49.82-50.11 Hz and is stored per event.
     Padding is 'line' (not zeros): zero padding pulls segment edges towards
     0 next to every dropout. The repair test (E_pipeline/dropout_repair_test)
     gave a median error of 2.7 sigma with 'line' vs 4.3 sigma with zero
     padding.
  5. Repair: output samples not covered by any segment (dropout holes) are
     bridged linearly. A FLAG mask also marks +-0.15 s around every split.
     The flag feeds mask_frac and repmask, but the guard zone is NOT bridged:
     bridging it made errors 3-5x worse.
  6. Baseline, two passes of a 20 s running median:
       pass 1 -> residual r1, robust sigma per 60 s block, B's hysteresis
                 detector (5 sigma on / 2 sigma off) marks events;
       pass 2 -> the running median is recomputed with pass-1 events AND C's
                 detections bridged out (+-2 s), so vehicles do not lift
                 their own baseline;
       r = y - baseline        (subtracted, never divided)
  Output: r, a baseline-subtracted ~50 Hz series in ADC counts, with no
  NaNs, plus the flag mask.

5.5 Cutting the event window  (pipeline.process_block, pipeline.cut)
--------------------------------------------------------------------
  - Centre: C's energy centroid, converted to the 50 Hz grid,
    jc = slot_centroid / 48.32.
  - Window: WIN_N = 1050 samples (~21 s; the length is the pre-registered p95
    of the 1-99 % energy extent of clean events), w0 = round(jc) - 525.
    Beyond a stream edge the window is zero-padded (zero = baseline) and the
    padding is flagged.
  - evmask[1050]  = True inside C's [onset, offset].
  - repmask[1050] = True where a sample was bridged, lies within 0.15 s of a
    split, or is padding.
  - mask_frac = fraction of flagged samples inside [onset, offset].
    Events with mask_frac > 0.2 are EXCLUDED (923, of which 873 are in run
    0204) and saved separately in excluded.parquet.
  - dur_s = (slot_offset - slot_onset) / (fs_eff x 48.32), in true seconds.

5.6 The 19 morphology features  (morph.morph_feats)
--------------------------------------------------
  Called twice per event:
      m_*  = morph_feats(w, fs_eff)                         21 s window
      m8_* = morph_feats(w[324:726], fs_eff)                central 402 samples
  Algorithm:
    x   = 5 Hz 4th-order Butterworth, zero-phase, designed at fs_eff
    sig = 1.4826 x median|diff(edge)| / sqrt(2), where edge = the first and
          last 1.5 s. This is a noise estimate made from sample-to-sample
          differences, so it is insensitive to slow residual drift.
    A   = max|x| at index ip;   pol = sign(x[ip])
    thr10 = max(0.1 A, 3 sig)   -> event extent [i0, i1] = first/last
                                   sample with |x| > thr10
    thr20 = max(0.2 A, 5 sig)   -> lobes: runs of x > thr20 (+1) or
            x < -thr20 (-1) lasting >= 0.1 s, with consecutive same-sign
            runs merged
    Crossing points l10/l50/l90 and r10/r50/r90 are found by walking left and
    right from the peak on x*pol.
  Changes from D's original (documented in morph.py):
    E1  uses the event's true fs_eff (D assumed 100 Hz built on 2400 Hz)
    E2  the 5 Hz smoother is designed at fs_eff (D's fixed 100 Hz filter
        would silently smooth at 2.5 Hz on 50 Hz data)
    E3  log_energy = log10(sum x^2 / fs + 1) is a time integral
        (about 2.003 lower than D's value)
    E4  guard: if no sample exceeds thr10, then i0 = i1 = ip (D raised an
        IndexError)

5.7 Selection, de-duplication, outputs  (run.py)
-----------------------------------------------
  - 16 processes run the blocks, longest first. Results are sorted by
    (run, core0), so the output is deterministic: two independent runs gave
    bit-identical files.
  - dedupe(): two consecutive events from different blocks whose
    [onset, offset] overlap are one event. The copy kept is the one from the
    block whose core contains the midpoint of the two centroids. One
    duplicate was found in the whole dataset.
  - event_id = "<run date>_<slot_centroid, 11 digits>",
    e.g. 20250204_00148106130.
  - Added columns: date, hour, snr_ge20, snr_ge30.
  - Assertions: event_id unique; windows float32 [N, 1050], all finite.
  - manifest.json records: command, package sha256 (the code is uncommitted),
    the vendored sha256s, all parameters, the chunk-index md5, counts per run,
    runtime and library versions.

6. THE FEATURES
--------------------------------------------------------------------------------

Notation: x is the 5 Hz-smoothed window, A is the peak |x|, pol is the sign
of the peak, and [i0, i1] is the 10 % extent. Units: counts are raw ADC
counts (baseline-subtracted); time is in true seconds.

 #  name             unit       definition / physical meaning
 -- ---------------  ---------  ---------------------------------------------
 1  log_amp          log10 cnt  log10(A). Peak field disturbance; grows with
                                vehicle mass and proximity.
 2  polarity         +1 / -1    sign of the largest excursion. Depends on
                                travel direction and lane relative to the
                                sensor axis.
 3  pos_frac         0..1       max(x)/A: size of the positive lobe relative
                                to the peak
 4  neg_frac         0..1       -min(x)/A: size of the negative lobe relative
                                to the peak. Bipolar events have both near 1.
 5  dur10            s          (i1 - i0 + 1)/fs: total duration above 10 %
                                (or 3 sigma). Related to vehicle length/speed.
 6  dur50_main       s          FWHM of the main lobe (r50 - l50)/fs
 7  rise_main        s          10 % -> 90 % rise time of the main lobe
 8  fall_main        s          90 % -> 10 % fall time of the main lobe
 9  asym             0..1       (ip - i0)/(i1 - i0): where the peak sits
                                inside the event
10  n_lobes          count      number of alternating-sign lobes above 20 %
                                (or 5 sigma) lasting >= 0.1 s. 1 = monopolar,
                                2 = bipolar, 3 = tripolar, ...
11  first_lobe_sign  +1/-1/0    sign of the first lobe
12  t_pp             s          (argmax x - argmin x)/fs: signed time from the
                                negative peak to the positive peak
13  area_pos_n       -          positive area in [i0, i1] / (A x dur10)
14  area_neg_n       -          negative area in [i0, i1] / (A x dur10)
15  log_area_abs     log10      log10(positive area + negative area + 1),
                                area in counts x s
16  log_energy       log10      log10(sum x^2 / fs + 1), energy in
                                counts^2 x s
17  t_spread         s          energy-weighted RMS time spread around the
                                energy centroid
18  zc_rate          1/s        zero crossings inside [i0, i1] / dur10
19  kurt_env         -          excess kurtosis of |x| (peakiness of the
                                envelope)

Time features: dur10, dur50_main, rise_main, fall_main, t_pp, t_spread
(seconds). Rate feature: zc_rate (1/s).

WHY m8_* AND NOT m_*:
  The pre-registration asked for morph on the 21 s window. On 21 s, dur10
  degenerates for low-SNR events (median ~20.8 s, i.e. the whole window) and
  absorbs neighbouring vehicles and the run-0204 dropout blips. At SNR >= 20,
  m_dur10 has a median of 8.1 s in run 0204 vs 4.6-6.4 s elsewhere, while
  m8_dur10 is flat across runs (3.1-3.4 s). The ~8 s crop is also the window
  length D validated. Use m8_* (and m8_dur10 for duration targets).

The model-facing representation recommended by D:
  (i) the waveform, amplitude-normalised (shape only), and
  (ii) the 19 morph scalars, which carry amplitude (log_amp) and polarity,
       normalised GLOBALLY with fixed scalings. Per-client z-scoring leaks the
       client's identity.
  The later SSL work (ssl_central/, research/model/) trains on the window
  arrays directly; morph is used as the hand-crafted benchmark and to
  derive probe targets.

--------------------------------------------------------------------------------
9. WHAT WAS REJECTED AND WHY
--------------------------------------------------------------------------------

The original repo fed the federation 70 EMD/HHT features per sliding window.
The re-design found:

  * int16 READ BUG. The old pipeline (comparison/central_pipeline.py:94 on
    branch origin/comparison-update) read the low 16 bits of each uint32 as
    int16. With codes around 11.5M, the int16 value wraps every 65 536
    counts, so a slow vehicle signal turns into sawtooth jumps. About 41 % of
    event windows were corrupted. Reproduced bit-exactly in the self-tests.
    The correct read is uint32 & 0xFFFFFF.
  * EMD/HHT is unsuitable:
      - On raw 2.4 kHz data, IMFs 1-5 are mains and noise (> 20 Hz).
      - The vehicle-dominant IMF index varies from 6 to 12, so "imfK_*"
        features are not comparable across events.
      - The IMF count changes under a 0.1 s shift for 34 % of events.
      - HHT features have the worst augmentation invariance (retrieval@1
        0.26-0.44 vs 0.89 for morphology).
      - CEEMDAN is more robust but ~120x slower and still loses.
  * DC-relative division: pointless (the divisor varies 0.975-1.009);
    subtract the baseline instead.
  * t_hours as a feature: it leaks the date (skill 0.98). Removed.
  * KMeans pseudo-labels for contrastive training: replaced by SimCLR
    augmentation pairs.
  * Per-client normalisation: increases client leakage (morph 0.02 -> 0.73).
    Use global normalisation.
  * Nominal 2400 Hz: wrong by ~0.7 %; fs_local is used everywhere.
  Consequence: the earlier federation results (federation_run*.log) are not
  trustworthy.

10. KNOWN LIMITATIONS
--------------------------------------------------------------------------------

  - There are no ground-truth labels. Detection precision rests on AI-labelled
    checks; the SNR >= 20 tier still contains some non-vehicles (telegraph
    steps, pulser spikes). A blind 80-plot human labelling pack is in
    research/extraction/C_detection/figs/human_pack/.
  - Tier boundaries depend on how sigma is estimated. Long context gives
    about 8 % lower SNR than short blocks.
  - The run-0204 dropout blips (0.5-1.1k counts, ~0.2 s, present in the raw
    data) remain in the windows. They are flagged only within +-0.15 s and
    are a route to run identity for learned encoders.
  - The detector's internal constants assume 2416 Hz (<= 0.3 % off in true
    time). All outputs are converted through fs_local.
  - Wall time is accurate to +-0.35 s.
  - extraction/ is not committed to git yet; manifest.json identifies the
    code version by package sha256.
