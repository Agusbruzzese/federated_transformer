# External audit: research/extraction/D_features

_20260930_103638 · served by claude-sonnet-5-5 · effort medium · 152651 in / 4456 out · ~$0.350_

## Verdict
**ACCEPT WITH FIXES**: the legacy-input finding (D1/D2) is well supported, but the feature ranking, the normalisation and augmentation advice, and the SimCLR-vs-KMeans conclusion rest on circular, non-stationary or unverified evidence. The report is also internally inconsistent in places, and the confidence labels overstate what was shown.

## Issues

1. [MAJOR] REPORT §0 D4 / §1 criteria: the top-2 "waveform, morph" claim is tied to pre-registered criteria, but the report says they were fixed "with PROTOCOL v1 added mid-run". Criteria such as the `large` subset, LP sweeps and SNR tiers were added after seeing the main result. The "13 settings" count includes many re-slicings of the same events and is not independent. -> State which criteria and slices were fixed before the first run. Report the 13 settings as correlated, not as 13 confirmations.

2. [MAJOR] evaluate.py `CRITERIA` / `rank_table`: the composite is a mean of ranks over 9 representations, including nested near-duplicates (legacy70, legacy_noconf, legacy_fixed_io, morph+wavelet). Several criteria (invariance, proxy, silhouette/ARI excess) are not comparable across dimensionality. The waveform is rewarded for silhouette and ARI excess against a column-permutation null, which is trivially near 0 for 256 correlated columns. The "excess" is therefore inflated by construction. The waveform's high ranks and "strongest cluster structure" come mostly from this artefact. -> Drop the null-relative cluster criteria for cross-dimension ranking, or use a null that preserves correlation structure (e.g. phase-randomised or shift-shuffled waveforms).

3. [MAJOR] evaluate.py `invariance` and the proxies: the invariance criterion favours the method that defined the augmentation geometry. Morph is computed on a 5 Hz-smoothed copy with thresholds, so it is nearly shift-invariant by construction. The proxies (log-duration, polarity, log-amp) are contained in morph's own features (acknowledged in the report, but the proxy stays in the composite ranking). The waveform is amplitude-normalised, so its log-amp R² ≈ 0.4 is by design. -> Exclude the circular proxy from the ranking, or evaluate it only on features excluded from the representation.

4. [MAJOR] REPORT §5.1 / evaluate.py `invariance`: "noise" augmentation adds a background window at its original amplitude. The waveform's noise R@1 is 0.97, while its shift R@1 is 0.05–0.71. Because the waveform is not shift-invariant, pooling shifts and noise into one "invariance R@1" (mean over NUIS) yields a number that mixes incomparable failure modes. The waveform score of 0.51 is also a Euclidean-distance artefact. The report admits no encoder was trained. -> Since the core recommendation (waveform into a 1D-CNN with SimCLR) was never tested with an encoder, downgrade D4 and the recommendation to "hypothesis". Train the encoder, or at least compare with a shift-aligned or cross-correlation distance.

5. [MAJOR] REPORT §0 D5 vs D4: D5 says "inconclusive for the full ordering" and stability is not met (ρ 0.77, and 0.47–0.53 against C's all-SNR events). D4 is still labelled "Medium" and the recommendation is stated flatly. The top-2 flips to {morph, legacy_fixed_io} on C's events, which is the detector actually recommended. "Stable" is reached only after restricting to tiers chosen post hoc (large, SNR ≥ 20/30). C's SNR tier is itself fitted on 20 labels. -> Downgrade the confidence. Say plainly that the ranking is conditional on the events being high-SNR.

6. [MAJOR] evaluate.py `leakage`: date and hour leakage is used as "lower is better", but the traffic mix genuinely varies by hour and date. Low morph leakage may partly reflect insensitivity. The holdout has only 3 days, partly partial (acknowledged). The report interprets "date leakage ~0" as cleanliness without checking that the signal is preserved. The 5-fold CV is random, not blocked in time, so near-neighbour events from the same minute sit in both train and test. This inflates leakage for the legacy features, so the contrast is overstated. -> Use grouped CV (by day or hour block) and report.

7. [MAJOR] REPORT §0 D1: the headline "41 % of event windows / 80 % of top tertile" disagrees with `wrap_audit.json` (event windows 0.4065; high tertile 0.804; chunks 0.107). This is consistent, but the wraps are counted on `RAW + dc_baseline` reconstructed from the float32 window. RAW was stored as float32 after subtracting dcraw and the baseline, so codes around 1.2e7 have lost precision (float32 has 24 bits of mantissa, so this is marginal at ±1). The reconstruction dc_baseline = dcraw + base[c] also differs from the true code by the baseline drift inside the window. Wrap counts are therefore approximate. Note also that the orchestrator's independent check on 60 chunks found 10 %, which does support the chunk-level rate. -> Mark the event-window rate as approximate, or recompute it from the raw codes.

8. [MAJOR] REPORT §3 legacy reconstruction: "legacy70" is a guessed reconstruction (PyEMD instead of `emd`, 8-s event windows instead of 60-s sliding windows, lost `add_dc_relative` guessed). The claim "legacy features leak date at skill 1.00" relies on t_hours, which is cumulative time by construction and so trivially predictive. Testing "t_hours predicts date" is tautological. The interesting result, legacy_noconf date skill 0.96 on holdout, depends on the guessed columns. -> Phrase D2 as a confirmation of an obvious property. Ablate the guessed relative columns separately.

9. [MAJOR] REPORT §0 D7 / §8: "KMeans pseudo-labels are unsound" relies on the column-permuted null, which is weak (see #2), and on k=5 only. `k_curves` exists but its results are not reported. The statement that the legacy 96 % accuracy is circular is asserted without checking the original training code (the client code is not in evidence here). Bootstrap-ARI "real 0.6–0.9 vs null 0.3–0.7" reads as stable structure. The report itself shows real ARI exceeding the null on most representations. -> Soften to "structure is weak/modest", report the k-sweep, and cite code for the circularity claim.

10. [MAJOR] REPORT §7 / norm_test.py: per-client "clients" are date × 4-h slots. The per-client z-score makes the client identifiable (leak 0.02 → 0.73), which is by construction, since per-client standardisation removes the mean and leaves the residual structure. The claim that this "injects the traffic mix" is partly tautological. The recommendation "global, not per client" is also not tested in a federated training loop. -> Label as a simulation result. Drop the inference about FedProx/FedBN, which is unsupported.

11. [MAJOR] REPORT §5.2 "sees dropout" and the exclusion of dropouts: the no-dropout subset is 1804 events from a dev set dominated by Run 0 (79 % of Run-1 windows have dropouts vs 14 % in the holdout). The dropout rate confounds with run. Removing dropout windows changes the run mix, so the nodrop-vs-all comparison is not clean. A composite ρ of 0.53 is dismissed as "noisy ARI ranking", which is post hoc. -> Report the per-run composition of the nodrop subset.

12. [MINOR] REPORT header / §2: D uses nominal 2400 Hz and ignores ticks. Feature time axes are −0.69 % off, and dropouts are ignored, so the windows are "centred" on an envelope peak of a detector that is not C's final one. All D conclusions come from the provisional detector (4 797 events), but the recommended "training on C tier" is evaluated only via the `check_C` path, which uses D's own LP/baseline rather than C's. Report this mismatch clearly. The claim "C's final detector produced the same event set" (§9 item 8) is unsupported: the md5 differs, and only the counts are the same.

13. [MINOR] evaluate.py `Scaler.fit` / main: the Scaler is fit on the events of the split, including the test folds used in CV, and PCA is fit on the full data. This is mild leakage for leakage and clustering metrics. The holdout is scaled with its own statistics instead of the dev statistics, which hides domain shift. -> Fit on dev and apply to the holdout.

14. [MINOR] compute_all.py `crop`/stretch: stretch uses `signal.resample` (FFT) on a windowed segment, which causes edge ringing. A shift of +0.5 s crops from a 12-s window centred at 600, so the baseline-subtracted signal differs slightly. `stretch1.15` with n = 696 samples taken around the window centre changes the content. The R@1 differences for stretch are therefore confounded. Also, `noise` adds a background LP window that has the same baseline treatment, but the RAW path adds `rb − median(rb)`, so the legacy set and the LP set do not get identical noise. -> Note this.

15. [MINOR] compute_all.py / reproducibility: the scratch paths are under `/tmp/claude-…/scratchpad`, and scan_all, compute_all and evaluate write there. The orchestrator's `run_queue*.sh` is not shown in full, and the eval subset relies on seed 42. Bootstraps use B=200, with a per-item bootstrap that ignores the clustering of windows within a block or day, so the CIs are too narrow (dependence). -> Use a cluster bootstrap (by day or chunk). Add a pinned events file to the repo.

16. [MINOR] REPORT §4 EMD audit: n=100, serial, with 1-seed EEMD/CEEMDAN (noise_seed 0). The statement "IMF count changes under real noise for 51 %" mixes the effect of noise with the effect of a doubled background. The CEEMDAN cost claim "120×" is a ratio of single-machine timings and is not a robust number. -> Give CIs, or label as indicative.

17. [MINOR] report_tables.md "Confound test" shows bg holdout null_shuffled up to 0.15 (n=260, 3 classes), which shows the null is noisy. Some "leakage ≈ 0" results (e.g. morph holdout date −0.01 [−0.06, 0.03]) are not distinguishable from the null at this n. -> State the power.

## Brief coverage
- D1 (audit EMD/HHT: IMF-count variability, mode mixing, shifts/noise, EEMD/CEEMDAN, cost): answered (n=100, single seed, no CIs).
- D2 (compare old 70 features, wavelet, STFT, morphology, raw waveform): answered, but the rankings are fragile and partly circular.
- D3 (label-free criteria: augmentation invariance, redundancy, confound leakage, cluster structure and ARI, proxies, valid augmentations): partial. The criteria are all implemented, but the cluster null is weak, the proxy is circular, the leakage CV is not blocked, and the augmentation validity rests on an argument.
- D4 (recommend representation, definitions, normalisation, KMeans vs SimCLR; deliver `features.py`): partial. `features.py` is delivered and a recommendation is given, but no encoder was trained, there is no federated test, the legacy-to-C consistency is unresolved, and the 12-s vs 21-s window question (from C) was skipped.

## Required follow-ups
1. Recompute the ranking without the circular criteria (proxy) and without the column-permutation null (use a correlation-preserving null). Check whether the waveform is still top-2.
2. Redo leakage with grouped CV (by hour block or day), and fit the Scaler on dev only.
3. Replace the per-item bootstrap with a cluster bootstrap by day/chunk. Report the power of the leakage nulls.
4. Report `k_curves` results, and KMeans stability at k ∈ {3…10}.
5. Train a small 1D-CNN with SimCLR on dev (torch is needed; install in a separate env), then compare its embeddings against morph on the same criteria. Otherwise, downgrade the recommendation.
6. Recompute the wrap rate from raw uint32 codes on the event windows, and record the per-run composition of the no-dropout subset.
7. Run the 12 s vs 21 s window comparison on C's clean tier, or state explicitly that it was not done.
8. Pin the event files and feature caches (md5) in the repository, and stop using `/tmp` scratch paths.
