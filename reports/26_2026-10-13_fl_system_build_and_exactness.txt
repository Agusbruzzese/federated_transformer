1. WHAT WAS BUILT
  - provision.py: splits fold 0 into 10 client folders (events, own-day
    noise, info with hashes) and a server folder (pinned server checkpoint,
    hash-checked) plus federation.json. Client sizes 434, 301, 81, 61, 324,
    297, 403, 53, 366, 253 (2 573 events): exactly the study's fold-0
    clients.
  - core.py: the simulator's local step, schedule, batching and FedAvg
    formula, copied verbatim. Clients never import study code; the frozen
    simulator reads the pooled noise file at import, which a client must
    never touch.
  - client.py: a long-lived Flower client (compat start_client). It keeps
    its own AdamW state, RNG streams and data on its own GPU context, and
    saves its state after every round (last 3 rounds kept) to roll back to
    the last committed round on restart. It checks its data hashes at
    start.
  - server.py: Flower server with a StrictFedAvg strategy. All 10 clients
    every round; aggregation in client order with the simulator's formula;
    it REFUSES to aggregate a round with any failure; it saves the global
    model every round (last + checkpoints) and can resume (--resume).
  - run_local.py: starts 1 server + 10 client processes on this machine,
    with a watchdog (a client that exits early stops the run instead of
    hanging) and fault injection.

3. DEFECTS FOUND AND FIXED DURING THE BUILD (honest record)
  a. The launcher created the run folder, and the server then refused it
     (FileExistsError). The server now accepts an existing folder but
     still refuses an existing rounds.jsonl (no overwrite).
  b. provision v1 stored day and event-id columns as Python object arrays.
     Clients (correctly) refused to load them without pickle. The fix
     stores fixed-width text arrays, in a new folder fold0_v2/ (fold0/ is
     kept as a superseded artefact).
  c. With all clients dead at start, the server waited forever. The
     launcher watchdog now stops the run when a client exits early.
  d. Design flaw found while planning T4, before it caused a failure:
     clients that completed an un-aggregated round would have been one
     round ahead after a restart. The fix is per-round client state with
     rollback to the last committed round.
  e. The first resume failed (RNG state loaded onto the GPU; it must stay
     on the CPU). Fixed and re-tested (t4_fault2 PASS). The failed attempt
     t4_fault is kept with its logs.
  f. An operational slip: a pkill pattern matched its own shell. No
     effect on data or results.
