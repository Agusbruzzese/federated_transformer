# External audit: orchestrator

_20260930_103828 · served by claude-sonnet-5-5 · effort medium · 11941 in / 3650 out · ~$0.060_

## Verdict
ACCEPT WITH FIXES: the orchestrator found real, valuable problems (corrupt legacy input, wrong format assumptions). But the synthesis states several decisions with more confidence than the evidence supports, relies on a stopping rule that closes workstreams on the orchestrator's own checks, and leaves the sole quantitative precision claim resting on AI labels. Only the audit verdict lines were supplied, not the audits' issue lists or the reports themselves, so many claims below can't be verified.

## Issues

1. [MAJOR] SYNTHESIS §1.1: "every earlier result built on the 70 legacy features is invalid, including federation runs (loss 0.48→0.35)". The evidence is that the int16 read is wrong and that about 10 % of chunks (about 41 % of event windows) jump. It does not follow that all results are invalid or uninformative, since 59 % of windows are clean. The "very high" confidence fits the bug, not the blanket consequence. The `pipeline.py`/`clustering.py` that produced the features are missing, so what they did with the corrupted signal is unknown. -> Separate "the reader is wrong" (verified) from "results are invalid" (inferred). Re-read a sample of legacy chunk windows correctly and compare them with the legacy features to quantify the damage.

2. [MAJOR] ORCHESTRATION_LOG, stopping rule: closure happens when a MAJOR either "has no effect on quantities the pipeline consumes" or "was checked by the orchestrator". The orchestrator is judging its own rule and closed A–D after few rounds. Several MAJORs were rebutted by the orchestrator (A issue 2, B issues 2, 6, 7, C issue 12) without an independent re-audit. Rejecting the auditor's "missing files" claim because the files were omitted for size is a transmission problem, not a refutation. -> Record each rejected or deferred issue with its evidence in a table. Have rebuttals reviewed by the auditor, or at least by a different agent.

3. [MAJOR] SYNTHESIS §2 Training tier: the default tier SNR ≥ 20 is chosen using D's "ranking stable" evidence. D's ranking is formally inconclusive (ρ 0.77 < 0.8 under PROTOCOL), and its proxies were judged circular. C's SNR cut was fitted on 20 passing items, and C says the precision figures are provisional. The tier choice therefore rests on weak evidence, and the tier is confounded with hour of day (48 % of the clean tier falls at 07–09 h). -> Mark the tier as provisional. Report the hour-of-day distribution of each tier, and check that the chosen tier does not make hour recoverable from the features.

4. [MAJOR] SYNTHESIS §1.6 and §2 (detector): "beats fair fixed-window baseline by ΔF1 +0.16 on holdout". Detection is evaluated by injection using templates taken from real high-SNR events, which were found by a 5 Hz detector and are of similar morphology to the detectors' template. Recall on small or distant vehicles is admitted to be optimistic, yet the detector is adopted as "validated". Run 3, the holdout, was touched during exploration, so it is not a clean holdout. -> Call the holdout "weakly held-out". Add a real-data check using human labels (the 80-item pack), and report recall by amplitude stratum.

5. [MAJOR] SYNTHESIS §4 and §5: the human-labelling pack is "optional, strongly recommended", yet the pipeline asks for approval before it exists. Precision, tier thresholds and detector parameters (5σ/2σ) all derive from AI labels. -> Make the human labels a gate for finalising thresholds, not an optional step. Do not run all 14 days on the final parameters before then. Running the extraction is cheap, so extract a superset and apply the thresholds later.

6. [MAJOR] Decomposition (LOG): running A, B, C, D in parallel while C and D depend on A's format is acknowledged to create inconsistency. It produced real waste: D used fs = 2400 and µs assumptions, and D's features were evaluated on events from a provisional detector. Synthesis says D's time features "must be rescaled when ported", and that D's conclusions are to be rechecked on C's events. The synthesis nevertheless relies on D's rankings without that recheck. -> Rerun D's headline comparisons (morphology vs waveform, leakage, augmentation invariance) on C's final events with B's chain and fs_local, before the synthesis uses them. At minimum, state that D's results were not recomputed.

7. [MAJOR] SYNTHESIS §2 Dropouts: the repair rule (mask_frac ≤ 0.2) combines B's, C's and A's different rules (fill 1–4 samples, split at ≥5, mask ±0.15 s, FIR-support mask). The combination was not evaluated end to end. Dropouts are the strongest confound (has_dropout predicts run with skill 0.34, density differs 10–20×). Repairing events in the dropout-rich run raises the risk that artefacts leak into the morphology features. -> Evaluate leakage with and without repaired events, and test whether the morphology scalars predict `has_dropout` or run.

8. [MAJOR] SYNTHESIS §1.2: "removing t_hours still leaves date skill 0.96 because of wrapped amplitudes". Attributing this to the wrapped amplitudes is causal, and the ungrouped CV and weak null that the D audit flagged also affect "skill" numbers. -> Re-test date and run predictability using grouped CV, on correctly read data, for the new feature set (not just for the legacy one).

9. [MINOR] SYNTHESIS §1.3: the "≈2416 Hz" rate and its dropout counts are stated with very high confidence, yet the log admits the attribution of the cause is medium confidence and absolute time accuracy (±0.35 s) is a lower bound. Clock drift ±0.2 %/day is conceded. -> Give the rate as per-chunk fs_local, with a spread, and do not use 2416 as a constant anywhere. The `resample_poly(25,1208)` = 50 Hz implies exactly 2416 Hz, so a per-chunk rate error of up to 0.2 % will shift the time axis. Check that this is consistent with the use of fs_local.

10. [MINOR] SYNTHESIS §3: the cost estimate of "about 2 CPU-s per hour" and "<30 CPU-min" comes from C's detector alone plus an unmeasured feature path. -> Measure the complete pipeline on a sample before quoting it.

11. [MINOR] SYNTHESIS §2 Representation: "19 morphology scalars (on the true fs)" are listed without definitions in the synthesis. The claim "morph top-2 in all 13 settings" is about ranking under weak criteria. -> Include the feature list and state that the ranking is exploratory.

12. [MINOR] Decision not to serialise A first (Audit 1 issue 1 not acted on): in hindsight A's findings invalidated assumptions in B, C and D. The log justifies the decision by cost but does not record the observed cost. -> Note the lesson and, for the model phase, serialise dependencies.

13. [MINOR] ORCHESTRATION_LOG: the orchestrator's own review (Audit 1) and the synthesis review are run by the same auditor family as the workstream audits, and the orchestrator chooses what to send. -> Include the audit files and the rebuttals in the package, so that the audit can check the accept/reject decisions directly.

## Brief coverage

- A3 (continuity, per-day coverage): answered by a full scan; the per-day table is not shown here.

- A5 (loader, self-test, index): answered (46/46 self-test), with caveats on cache versioning and paths.

- B3 (events, gallery): answered, but the sample was biased toward per-chunk events with edge truncation.
- B4 (artefacts, DC normalisation): answered (subtract, don't divide).

- C1 (evaluation spans): partial (holdout lacks weekend and dense dropouts).
- C2 (≥4 detectors): answered.

- C4 (overlap, drift, boundaries, gaps): answered, with no end-to-end check of the repair.
- C5 (recommendation, detector.py): answered; parameters are provisional.
- D1 (EMD audit): answered.
- D2 (representation comparison): answered, but run on a provisional detector and fs = 2400.
- D3 (label-free criteria): partial (circular proxy, weak null, ungrouped CV, no encoder).
- D4 (recommendation, features.py): partial (deferred to the model phase, i.e. a superset; KMeans vs SimCLR unresolved).
- Brief design overall: the briefs asked each workstream to pre-register but did not require the serial dependency on A, did not require any human labels, and did not require cross-workstream re-evaluation on shared events. These are design gaps.
