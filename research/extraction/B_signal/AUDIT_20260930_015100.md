# External audit: research/extraction/B_signal

_20260930_015100 · served by claude-sonnet-5-5 · effort medium · 93243 in / 2809 out · ~$0.215_

## Verdict
ACCEPT WITH FIXES: Brief B is largely covered with substantial, mostly traceable evidence. However, the events-per-hour rates, the 8 Hz cut-off, the "no run difference" claim and several confidence labels are overstated or partly circular, and some numbers cannot be reproduced from the shipped scripts.

## Issues

1. [MAJOR] REPORT §3.5, S12 / `synth.py`, `cutoff2.py`: The 8 Hz "minimax" cut-off is circular and rests on a selected event set.
   - Templates are the 40 largest real events (>10k), LP 40 Hz, and are time-compressed to make "4× faster" events. There is no evidence that such fast events exist; the "4× matters" justification cites the p5 rise of the same detector output.
   - The 8σ events used in `cutoff2.py` were selected by a 5 Hz-LP detector, so fast, small events are under-represented.
   - The minimax claim is restricted to ≥1500 counts, and the orchestrator note says 2 Hz wins at 700 counts. Confidence "medium-high" is too high.
   - -> Downgrade to medium/low. State that the cut-off depends on the assumed speed prior. Report the selection effect of the detector.

2. [MAJOR] REPORT §3.4 hourly rates / S8 / S9: Rates are inferred from every 8th chunk plus 11 windows, with one Saturday. The bootstrap-by-day CI treats days as exchangeable (14–16 days per hour).
   - Hourly rates are per-detector and threshold-specific, and they depend on a ≥0.4 s cut and a mask_frac ≤0.2 rule that was added after v1.
   - The "17.7 % extent >8 s = merged" and "7.1 % overlap" figures are lower or upper bounds mixed together. Extent above 2σ is not a merge indicator.
   - -> Describe the rates as detector-relative. Drop "rush-hour overlap not negligible" as a finding, or label it exploratory.

3. [MAJOR] S8 / §3.4 amplitude modes: The threshold 5000 counts to define "large" is chosen from the histogram valley and then used to define the class for all later statistics (S6, S7, day/night, run comparisons). This is circular, and the class stats are truncated by construction.
   - The report itself concedes the lower mode moves with the trigger.
   - -> Treat "large" as an amplitude-selected subset, not a population, and say so in S6/S7.

4. [MAJOR] §3.4 per-run test / `v2_analysis.py`: "No difference in run-0204 morphology detectable" is a null result from Mann-Whitney on n=40 vs n=290, with no power analysis or effect size.
   - The run 0 sample is restricted to clean, ≥5 s-from-edge events, which excludes the dropout-affected ones that matter.
   - Repaired events are compared only on summary medians.
   - -> Report effect sizes and CIs, and soften the claim.

5. [MAJOR] S10 blip cause: The classification uses duration <0.4 s and vehicle-like uses ≥0.4 s, then shows the classes differ in run and dropout association. Some of that is definitional.
   - The report labels the mechanism "medium" while still calling them "logger blips" in the S10 title and in the v1 text.
   - -> Rename to "short detections correlated with dropout load".

6. [MAJOR] Reproducibility: Several quoted numbers have no script.
   - The orchestrator note says spike numbers were originally an inline check. `spike_check.py` now exists, but the v1 spike text (600/h) differs from v2 (684/h).
   - `fig_gallery.py` and `fig_contiguous.py` still load v1 `events_classified.parquet` and `contiguous_lp100.npz`, and `contiguous.py` uses the old chunk_stats path.
   - `out_baseline.txt` and `out_v2_analysis.txt` were not provided, so the structure-function and rate tables cannot be checked.
   - `noise_vs_fc.py` depends on `v2_quiet.pkl`, which is drawn from windows only, so the "noise σ" comes from 29 stretches.
   - -> Add a run-all script with seeds. Mark the v1 scripts obsolete. Ship the out_* files.

7. [MINOR] `preproc.slots`: The gap threshold is 1.5·median(dt), where the median dt is taken per span. Ticks are not µs, and fs varies by 3–4 Hz with hour.
   - Losses of 1–4 samples are linearly interpolated, which fills gaps that A counts as real loss.
   - The `edge` exclusion in `clean_span` trims 1 sample, but the LP `padlen` is only 3 s, so edge effects for spans ≤ 41 s chunks are large.
   - -> Quantify the edge distortion. Use `edge_dist` filtering consistently, including the rate tables (the rates use mask_frac only).

8. [MINOR] `run_pipeline.py`: The quiet stretches are selected from windows that contain events, at random with `default_rng(len(label))`. The seed is derived from the label length, so different windows with equal-length labels share seeds.
   - Snippet extraction requires [a−6 s, e+6 s] in one segment, so the cut-off test excludes events near dropouts, which is the population most at risk.
   - -> Use an explicit seed. Document the selection.

9. [MINOR] S1 and clock: fs = 2416 Hz is derived from the mains, which is assumed to be exactly 50 Hz. The report claims ±0.1 % while chunk-level values span 2407–2421 (±0.3 %), and A finds a diurnal dip of 3–4 Hz.
   - Durations therefore carry a ±0.3 % error, which is small but inconsistent with the stated ±0.1 %.
   - -> Correct the stated uncertainty.

10. [MINOR] `cutoff2.excess_fraction`: The negative excess fractions (−1 % to −11 %) show that the flank-noise model is biased.
    - The conclusion "no content above 2 Hz" for small events is therefore not supported. The report admits this, but S12 still leans on it.
    - -> Do not use it as evidence.

11. [MINOR] Pre-registration: The brief requires pre-registered criteria. None is stated, and the orchestrator-caveat fixes (edge exclusion, mask_frac ≤0.2, v2 rewrite) were made after seeing results.
    - -> State explicitly that criteria were post hoc.

12. [MINOR] S11 (divide vs subtract): "Dividing is unjustified" rests on a ±1.6 % code variation, and it is argued against the sensitivity being unknown. It is not tested. No downstream metric was compared.
    - -> Keep at "medium" and flag it as an untested design choice.
