# External audit: research/model/M5_long

_20261002_084233 · served by claude-sonnet-5-5 · effort medium · 12028 in / 2007 out · ~$0.044_

## Verdict
**ACCEPT WITH FIXES.** The pre-registration is mostly well structured, but it has internal contradictions, ambiguous decision rules, and unflagged consistency risks, and it contains no results yet. Several rules must be fixed before any M5 code runs.

## Issues

1. [MAJOR] PREREG §Honesty/Data split: the test days were already seen in M4, and hyperparameters and probe choices are "fixed from M4's selection". Both selection and the M5 rules are therefore informed by the test set. Calling the test "confirmatory" is overstated. -> Label every M5 result "exploratory, post-selection". Carve out a truly held-out day, or state that no confirmatory claim is possible.

2. [MAJOR] §Statistics, Q1 rule: "beats each of B1–B4 on ≥2 of 3 scores, and loses to none on any score" conflicts with "beats" requiring both probes, a gap ≥0.02 and a Holm-adjusted p<0.05 with the CI excluding 0. With 2 000 bootstrap resamples, the minimum attainable p is ~1/2000, so Holm over 84 tests per probe is borderline. The Holm adjustment is also not defined for a bootstrap CI. -> Specify how a Holm-adjusted p is derived from the bootstrap, and use ≥10k resamples. Define "loses" using the same threshold. State how ties and the "neither" case are treated.

3. [MAJOR] §Statistics, bootstrap: only 167 test blocks from 4 days, and events are clustered within blocks and days. Block resampling ignores day-level correlation. Seeds are resampled independently across pairs, while a "same blocks for both members of a pair" rule is applied only to blocks. Seed variance is entangled with the test-set variance. -> Resample days or blocks hierarchically, report the number of effective clusters, and temper the p-values.

4. [MAJOR] §Probes, baseline scaling: the baseline scaling is chosen on a single validation day (327 events), which gives high-variance selection. The SSL methods get no equivalent per-probe tuning of their embeddings (fixed z-scoring). B2 has 1 536 dimensions vs 64 for SSL, so the linear probe and kNN comparison is confounded by dimensionality and C=1 regularisation, which are untuned for B2/B3. -> Apply the same selection rule to all representations, or use a dimension-matched comparison (PCA-64 for B2/B3) as an additional rule.

5. [MAJOR] §Gates, G1: the MAE gate compares against linear interpolation of normalised patches. That is a weak and possibly trivially passable or failable bar, depending on patch size relative to smoothness. The fixed mask seed is not specified. The "≥3 of 5 seeds fail" threshold is arbitrary. G2's "exceed own untrained weights" has no margin or CI. -> Specify the mask seed, require a margin, and define G2 numerically.

6. [MAJOR] §Q3: the conditional-leakage design has a threshold Δ>0.05 with no uncertainty estimate. The "max over two probes" is biased upward. PCA-reducing to ≤32 dims for the embedding but whitening morph8 (a different treatment) is ambiguous. The Δ for the baseline representations (B3/B4) is not specified for the flag, so calibration is unclear. GroupKFold by 30-min block still leaks run identity via neighbouring blocks on the same day, and "is-0204" is almost a day-level label. -> Add a CI for Δ, use the max-over-probes null distribution, and group by day, or at least show the test-day-grouped result.

7. [MINOR] §Training: 10 steps per epoch with batch 256 on 2 636 events means ~1 000 epochs, which invites overfitting. No early stopping or checkpoint rule is stated, nor which checkpoint is evaluated. -> State that the final-step checkpoint is evaluated, and log the training curves.

8. [MINOR] §Targets: "lobes skill, capped at 4" and the target definitions rely on upstream morph features (the `dur10` choice). The label-free targets are derived from the same morph features as the "ceiling" Ref, which is partially circular for the morph8 comparison. -> Note this as a limitation.

9. [MINOR] §Reproducibility: the seed scheme is only partly stated (the initialisation seed of B1/B2 is reused from the SSL seeds, so the "untrained" baselines share the init of the trained models, which is good for G2 but correlates them). The pip environment, code commit and file list are not pinned. -> Pin the commit and data manifest hashes.

10. [MINOR] §Tier: SNR≥20 selection retains ~29 % of events, and A/C/E document the bias toward high-SNR morning events. -> Repeat the headline on the SNR≥30 tier, or state the restriction in every conclusion.
