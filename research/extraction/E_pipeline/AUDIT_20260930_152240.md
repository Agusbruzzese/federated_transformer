# External audit: research/extraction/E_pipeline

_20260930_152240 · served by claude-sonnet-5-5 · effort medium · 52571 in / 2927 out · ~$0.134_

## Verdict
ACCEPT WITH FIXES: The pipeline is plausibly implemented and the counts are internally consistent. The report overclaims on validation, on the "explained" rate discrepancy, and on the morph/leakage evidence. Several design choices were made after seeing results, and the extraction package is not in version control.

## Issues

1. [MAJOR] REPORT §0/§4a, rate_vs_C_sample.py: "Explained, not a pipeline error" is asserted, but the explanation (short-block SNR ~8 % high) is not tested. The mechanism is an inference from a median E/C SNR ratio of 0.92, not a controlled experiment. On C's own windows E is still 17–20 % below C at SNR ≥ 20 (13.57 vs 16.34). Only 68 % of C's events match at all, and 15 % of C's SNR ≥ 20 matches fall below 20 in E. Standalone C with 3 context chunks matches E, but that only shows E reproduces C given long context. It does not show which SNR is "right". -> Run C with the short context on the E span to show the SNR shift directly. Downgrade "explained" to "consistent with", and state which σ estimate defines the tier.

2. [MAJOR] REPORT §4a/§4c: The tier threshold (SNR ≥ 20) is not validated against any labels. The gallery is a single AI viewer's judgement of 30 windows, with no counts of vehicle vs non-vehicle. The report itself lists telegraph steps, pulser spikes and near-noise events inside the tier, yet still recommends the tier "as pre-registered". -> Report a fraction (with a CI) of non-vehicle events from a scored sample, or state that precision is unknown.

3. [MAJOR] §4d leakage, validate.py `leakage()`: The stated criterion (date skill ≈ 0) is met only after restricting to SNR ≥ 20. At SNR ≥ 20, run skill is 0.144 and 6-h bin skill is 0.35 (which the report reads as a "genuine traffic mix" without testing). The SNR ≥ 30 numbers use n = 419 groups with a noisy null (−0.03). The has_dropout comparison (0.142 vs null 0.129) has 18 groups, which is low power for "no evidence". The reading "not a pipeline defect" is a hypothesis: the pooled all-tier leak is partly explained by a run-0204 blip population, but the causal link to dropouts (§4c) rests on two events. -> Quantify blip prevalence near vs far from dropouts across the whole of run 0204. Report null distributions with repeats, not one permutation (`rng.permutation` is drawn once).

4. [MAJOR] §5 dev. 9 / `m8_*`: The `m8_*` features and the `m8_dur10` recommendation were added after seeing that `m_dur10` degenerates. This is a post-hoc change to the pre-registered target. `m8` was also evaluated on the same data used to choose it. The "flat across runs (3.1–3.4 s)" claim is not backed by a saved table. -> Label it exploratory, save the per-run table, and get the orchestrator decision before F uses it.

5. [MAJOR] §2 dropout_repair_test.py: The design choice ("line" padding, hole-only bridging) is tuned on 20 events at SNR ≥ 30, from runs 0218/0224 only, with 9 offsets each (180 placements are pseudo-replicates, not independent). It is not tested on run 0204, which is dropout-dense and the run where it matters. Note also the ±0.15 s bridged variants have p90 error 17 % of peak, so "flag, not bridge" leaves the raw 105-sample discontinuity in features whose window sits within 0.15 s of a split. The decision is not validated on events with a real dropout. -> Test on run 0204 and on low-SNR events. Report per-event medians with CIs.

6. [MAJOR] Code identity / reproducibility: `extraction/` is uncommitted (dev. 15). The manifest records a package sha256, but nothing pins the vendored copies against later edits (bsd_io has an `E-PATCH`). Seeds are set for the gallery and leakage. The `crosscheck_morph` seed is 5 and the pick is 5 events. -> Commit the code and tag it before phase F.

7. [MINOR] §4e2 morph cross-check: n = 5 events, no summary statistic. One event disagrees by 0.12 in neg_frac and 0.17 in kurt_env, and this is dismissed as a "near-tie". "Agrees to within quantisation" is overstated. Only the chosen fs correction is compared, so a shared error would go undetected. -> Use ≥ 100 events and report a distribution of differences.

8. [MINOR] §4e1 spans: The two 2-h spans were chosen by the agent (one dropout-dense). Standalone C is given exactly the same slot-based `t` (dev. 1), so agreement is partly circular. Unmatched events reach SNR 16.7 (C) / 14.3 (pipe), while "all SNR ≥ 20 matched" hides that run 0204 has n20 C=20 vs pipe=22, i.e. 2 extra events in the pipeline that C did not find. -> Report this asymmetry and use a third span (a night span).

9. [MINOR] §0 "dur_s"/time: Wall-time accuracy of ±0.35 s is borrowed from A. A's own summary shows fs_local is known only to ±1.2 Hz per chunk (0.05 %), yet `fs_eff` is stated to 3 decimals (49.816–50.113) and the tests assert exact time-scale recovery. Durations therefore carry ≈ 0.05–0.3 % uncertainty (B's addendum says ±0.3 %), which is not propagated. -> State the uncertainty on `dur_s` and `fs_eff`.

10. [MINOR] validate.py `counts()`: Run assignment for hours in `tab_runs.csv` uses hard-coded date cut points (Feb 1/12/17/23/Mar 1). Runs share dates (run 0204 spans to Feb 11, and Feb 11 hours are attributed to run 0). Per-run rates depend on this binning. Recorded hours per run are cross-checked only against the manifest total. -> Take run membership from the chunk index.

11. [MINOR] Diurnal claims: the "night ≤ 3/h" and "weekend flat" statements pool 2 weekend days and few nights. The Poisson CIs assume independent events, which ignores day-to-day clustering. Hour-of-day is on the PC clock, and the drift is unquantified. -> Add per-day dispersion.

12. [MINOR] Cross-workstream: The C tier rates (16.3/12.1) are now contradicted. C's bias-corrected clean-tier count (~4.1k) sits next to E's 4,375 for SNR ≥ 20, but C's "clean tier" and E's SNR ≥ 20 are different definitions. -> Confirm which tier phase F trains on.
