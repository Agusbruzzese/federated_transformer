SUMMARY
-------
SecAgg+ works. The server decodes only the weighted sum of the 10 sites'
updates, the decoded sum is correct within the theoretical quantisation
bound, and the vectors the server receives from each site carry no
measurable trace of that site's true update. M3a, M3b PASS.
M3c FAILS its pre-set criterion: seed 1 differs from the study model by
-0.0186 on LOBES (criterion <= 0.01 per seed). Seeds 0 and 2, and POLARITY
for all seeds, are within the criterion. Section 4 explains the failure and
gives an exploratory (NOT pre-registered) analysis: the SecAgg+ effect is
the size of ordinary seed-to-seed variability and within the study's
equivalence margins. This does not overturn the criterion's verdict.

1. DESIGN AS IMPLEMENTED
  - Each site trains exactly as in M1 and sends its update
    delta = new weights - global weights, with weight n_k = s_k * b_k
    (examples seen). Flower's SecAgg+ multiplies by n_k / max_weight
    before masking and divides after decoding, so the decoded result is
    FedAvg's weighted mean of the deltas. The server adds it to the global
    model.
  - Settings (fixed before the full runs, from measured update sizes):
      shares 10, reconstruction threshold 7, clipping range 0.5,
      quantisation range 2^22, modulus 2^32, max_weight 896.
    Measured maximum |update| over all 600 full-run rounds: 0.025, i.e.
    20x below the clipping range; 0 values clipped.
  - Stochastic rounding is seeded per (seed, site, round), so every SecAgg+
    run is reproducible, but it is NOT the same arithmetic as plain FedAvg:
    each round adds a quantisation error of order 1e-7.
  - Strict rule kept: any failure in any of SecAgg+'s stages stops the round
    (no dropout recovery used).
  - Flower detail found and handled: the masked vector a site sends has one
    extra leading element (the weight factor); the tests drop it before
    comparing.

3. WHY M3c DIFFERS AT ALL
  Plain FedAvg in M1/M2 was bit-identical to the study, so any difference
  here comes from SecAgg+ itself, specifically from quantisation (about
  2e-7 per value per round). Training over 200 rounds amplifies such tiny
  perturbations: the final weights differ by up to 0.066 although each
  round's error is 1e-7. This is the same mechanism that makes two training
  seeds end in different models. The criterion "<= 0.01 per seed" was
  taken from T2, where the system was expected to be exact; for a method
  that perturbs the arithmetic on purpose it compares against a
  difference smaller than the natural seed variability (section 4). That
  is a weakness of the criterion chosen in report 30, but it was fixed in
  advance, so the result stands as a FAIL.

4. EXPLORATORY ANALYSIS (NOT PRE-REGISTERED; does not change sec. 2)
  Question: is the SecAgg+ effect larger than seed variability, and is it
  within the study's equivalence margins? Per-day scores (fold 0
  evaluation days 2025-02-05, 02-11, 02-25) x seeds 0-2, frozen evaluator,
  same paired and two-stratum procedures as the study (90 % CIs):

    metric    margin  mean diff  paired 90% CI        two-stratum 90% CI
    LOBES     0.04    -0.0047    [-0.0320, +0.0226]   [-0.0346, +0.0252]
    POLARITY  0.02    +0.0014    [-0.0083, +0.0110]   [-0.0074, +0.0102]
    DURATION  0.03    +0.0024    [-0.0014, +0.0062]   [-0.0006, +0.0054]

  All three CIs lie inside the margins (equivalence by the study's rule).
  Seed variability of the study's own S+F models on fold 0: SD of seed
  means 0.018 (LOBES), 0.0043 (POLARITY). The largest SecAgg+ seed
  difference is 1.0 SD (LOBES) and 1.8 SD (POLARITY).
  Limits: 3 seeds, 1 fold, 3 days; the analysis was chosen after seeing
  the M3c result; the LOBES CI (width 0.055) only just fits the margin.
  It suggests, but does NOT prove, that SecAgg+ leaves learning equivalent.

5. VERDICT
  M3a, M3b PASS: secure aggregation is correct and hides individual
  updates. M3c FAILS its pre-set criterion (seed 1, LOBES). Exploratory
  evidence suggests the difference is seed-level noise within the study's
  margins, but that claim needs a pre-registered test. M3d: +29 % time.
  To settle M3c properly (proposal, not executed):
    M3c' pre-registered equivalence test: SecAgg+ vs plain, 10 seeds,
         fold 0 (or all 3 folds), study margins and TOST rules, analysis
         fixed before running. Cost: about 2.2 h GPU per run, 22 h for 10
         seeds on fold 0 (the plain runs already exist).

6. WHAT M3 DOES NOT DO
  - SecAgg+ hides each site's update from the server, not the aggregate:
    the global model still carries information about all sites together.
    Only differential privacy (M4) bounds that formally.
  - Security assumes at most 3 of 10 parties colluding with the server
    (threshold 7) and an honest-but-curious server; it does not protect
    against a server that changes the protocol.
