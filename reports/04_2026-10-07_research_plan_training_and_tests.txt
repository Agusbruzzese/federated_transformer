SUMMARY
-------
The model is not what limits the project. The evaluation is.

The encoders train, do not collapse, and learn waveform structure (lobe count
most robustly). But every test so far uses targets computed from the same
morphology features (circular), an untrained CNN already nearly saturates two
of the three targets, and all 340 h of data have been looked at. More
architecture or hyper-parameter tuning against these proxies cannot answer the
question that matters: does the representation tell us anything about
VEHICLES?

So the plan is, in order:
  Phase 0  Define the downstream task and obtain ground truth (labels and
           fresh, untouched test data). This is the critical path.
  Phase 1  Fix the data foundation: measure detector precision, recover the
           low-SNR events, decide on amplitude.
  Phase 2  Train with a design driven by the task: augmentations chosen for
           the invariances the task needs, fixed hyper-parameters, collapse
           gates, 5 seeds.
  Phase 3  Run a fixed, pre-registered test battery (T1-T12 below), with
           planted-control dry runs before any real scoring.
  Phase 4  Only then move to federated training, with this central model as
           the benchmark.

Every phase has an explicit stop/go criterion (section 7).


--------------------------------------------------------------------------------
1. DIAGNOSIS: WHAT LIMITS US NOW
--------------------------------------------------------------------------------

1.1 There is no downstream task. "A good representation" is undefined until
    we say what it is for. The dataset title says "Vehicle Detection and Car
    Model Recognition". Candidate tasks, in increasing difficulty:
      a. vehicle vs non-vehicle (detection purity);
      b. direction of travel / lane;
      c. coarse class (car / van / truck / bus / motorbike);
      d. speed and length;
      e. same-vehicle or same-model recognition (re-identification).
    Each task needs different invariances (section 4.2). Speed, for example,
    is a nuisance for (e) but the target for (d), so time-stretch
    augmentation helps one and hurts the other.

1.2 The targets are circular and saturated.
      - polarity, lobe count and duration are functions of morph8, so morph8
        is the ceiling by construction;
      - an untrained CNN reaches polarity 0.885 and duration R2 0.82, so
        there is almost no headroom;
      - the M5 decision rule had about 5 % power against a +0.05 gain.

1.3 There is no fresh test data. M5's test days were seen in M4; run 0218
    was used to design the detector. Every further experiment on these 340 h
    is exploratory.

1.4 The input throws away information that a vehicle task may need.
      - Max-normalisation removes amplitude (vehicle mass, distance).
      - SNR >= 20 drops 71 % of events (far lane, small vehicles).
    Both were reasonable for shape learning and leakage control, but neither
    has been tested against a vehicle task.

1.5 Detector precision is unknown. The 80-panel blind pack
    (research/extraction/C_detection/figs/human_pack/) has never been
    labelled.

Conclusion: the next useful unit of work is not a training run; it is data.


--------------------------------------------------------------------------------
2. METHODOLOGICAL RULES (lessons from phases F-M5 and the critiques)
--------------------------------------------------------------------------------

  R1  State the question, the target and the minimum effect of interest
      before running anything. Pre-register; log deviations.
  R2  Test the test first. Every criterion must be shown to FAIL on a planted
      negative control and to PASS on a planted positive control before it is
      frozen. (The v3 pooling error and the M5 MAE gate error would both have
      been caught this way.)
  R3  One model, one embedding space. Never pool embeddings from different
      networks into one probe.
  R4  The control for "did training help" is the same network's own init.pt,
      plus raw, PCA and an untrained CNN.
  R5  Fix hyper-parameters from earlier phases. Selection margins were
      <= 0.009 in G: tuning is noise. Spend compute on seeds and controls.
  R6  Hold out by run or day (the future federated clients), never by random
      event split. Bootstrap by day, then by 30-minute block.
  R7  Do a power calculation before freezing a decision rule. Restrict the
      test family to the comparisons that matter.
  R8  The test set is touched once. Freeze it (hash the event IDs), score
      once, publish whatever comes out.
  R9  Verification means recomputing, not re-reading. At least one primary
      number and one leakage number are recomputed independently per phase.
  R10 Proxy targets (polarity, lobes, duration) are regression tests (to
      detect that something broke), not evidence of success.


--------------------------------------------------------------------------------
3. PHASE 0: GROUND TRUTH (critical path)
--------------------------------------------------------------------------------

Options, from cheapest to most valuable. They are not exclusive.

0A  Label the existing blind pack (about 30-60 min, no new data).
    80 panels, codes V/M/F/N/U (README in the pack folder). Output:
    detector precision per SNR tier with Wilson confidence intervals.
    Answers: "is SNR >= 20 really vehicles?" and "how much of SNR 5-20 is
    usable?"

0B  Look for existing labels at the site.
    The recording site is "INL GATE - Much After Barrier". If the barrier or
    the gate has an access log, a badge log, licence-plate reads or a
    security camera, its timestamps can be matched to our events (event wall
    time is accurate to +-0.35 s; SNR >= 20 events arrive about 13 per hour,
    so matching is easy). Even a few days of a barrier log give
    vehicle/non-vehicle and possibly vehicle identity (repeat visitors).

0C  Record a short labelled session (one day of fieldwork, if the sensor can
    still record at the same spot).
      - Video the road for 2-4 h at peak time (08-10 h) with a phone. Note
        for each passage: time, direction, lane, class (car/van/truck/bus/
        motorbike) and, if visible, make/model.
      - Clock sync: drive a known car past at noted times at the start and the
        end of the session. These passages also serve as sync markers.
      - Target: >= 300-500 labelled vehicles over >= 2 sessions or days.

0D  Controlled passages (the strongest single experiment for "car model
    recognition").
      - 3-6 known vehicles of different models (colleagues' cars, a van).
      - Each passes 10-20 times, at 2-3 speeds, in both directions, in both
        lanes if possible.
      - This gives TRUE same-vehicle positives, which nothing in the current
        data provides. It separates vehicle identity from speed, lane and
        direction, and tests directly whether the augmentation-invariances
        are the right ones.

0E  Fresh, untouched test data.
    If the sensor is still deployed, record >= 2 new weeks, hash the event
    IDs on arrival and do not look at them until the final test (rule R8).
    This restores a true held-out set.

Minimum viable Phase 0: 0A plus one of 0B/0C. Without any of 0B-0E, the
project can only make claims about waveform shape, not vehicles.

Rough size needed: comparing two models on the same labelled test events, a
paired difference of +0.05 in balanced accuracy needs on the order of
300-500 test events spread over >= 6 days or sessions. Confirm this with a
simulation-based power analysis before freezing (rule R7).


--------------------------------------------------------------------------------
4. PHASE 1 AND 2: DATA FOUNDATION AND TRAINING DESIGN
--------------------------------------------------------------------------------

4.1 Data foundation (Phase 1)
  a. Detector precision from 0A. If SNR 5-20 events are mostly vehicles once
     the run-0204 dropout blips are removed, add a blip filter (short,
     ~0.2 s, 0.5-1.1k-count excursions near flagged dropouts) and use the
     larger set for PRE-TRAINING (about 3x more events). Labels and test
     events stay where they are.
  b. Amplitude. Test three input variants against the labelled task:
       (i)   shape only (current);
       (ii)  shape + log peak amplitude as an extra scalar input, globally
             scaled (as recommended by workstream D);
       (iii) shape + morph8 scalars (hybrid).
     Amplitude is a likely cue for class (mass) but also correlates with
     distance and noise floor, so it must be checked for leakage (T8).
  c. Keep SNR >= 20 for EVALUATION, and report results by SNR band.

4.2 Augmentations follow the task (Phase 2)
  An augmentation is a statement: "the model must ignore this". Choose them
  from the target task, and test each with a leave-one-out ablation (T10).

    augmentation         makes the model ignore  good for       bad for
    -------------------  ----------------------  -------------  ------------
    time-stretch         speed                   class, re-ID   speed, length
    amplitude scale      distance, mass (part)   shape tasks    class (mass)
    real noise           sensor/background       all            -
    DC offset / drift    baseline wander         all            -
    random crop/shift    detector jitter         all            -
    (forbidden) sign     polarity                -              direction
    (forbidden) reverse  time order              -              direction

  The current stretch range (0.85-1.18) is suspected of removing duration
  information from the CNN (0.815 -> 0.771). Test 0.95-1.05 and no stretch.

4.3 Architecture
  Keep the two existing backbones; do not add new ones until labels exist.
    - CNN (210k parameters): strong untrained prior, best on lobes.
    - Patch transformer (207k): preferred for federation (cleaner on leakage),
      best on duration under a linear probe.
  One planned ablation: transformer patch size 0.5 s -> 0.1-0.2 s.
  A small conv stem before the transformer is a reasonable later candidate.

4.4 Objective and recipe (fixed from M5 unless a test says otherwise)
  SimCLR, AdamW lr 3e-4, weight decay 1e-4, batch 256, T = 0.1, 10k steps,
  5 % warm-up then cosine, 30 s false-negative guard, 5 seeds.
  VICReg as the second objective (cleanest on leakage).
  Optional, only with labels: supervised fine-tuning or SupCon with real
  labels on top of the SSL weights.

4.5 Training-time gates (must pass before any test scoring)
  G1 Loss decreases; no NaN; final loss within the range of earlier phases.
  G2 No collapse: effective rank of the 64-d embedding >= 15; per-dimension
     standard deviation > 0; alignment and uniformity (Wang & Isola, 2020)
     reported. C1 saw 2 of 5 seeds collapse in a clustering sense, so this
     gate is real.
  G3 Better than own init on validation by a pre-stated margin.
  G4 Determinism: two embedding passes bit-identical; the config hash is
     logged.
  G5 Firewall: no test or validation event ID in training (asserted on IDs).

5. PHASE 3: THE TEST BATTERY
--------------------------------------------------------------------------------

Each test lists: the question, the method, and the pass criterion or what is
reported. "Labels" means Phase 0 labels. Tests marked [now] can run on the
current data; the others need Phase 0.

T1  Pipeline dry run with planted controls [now]
    Q  Can each criterion pass and fail?
    M  Run the complete evaluation on: random-init embeddings; random-init +
       a planted run/day one-hot (must FAIL leakage); random-init + a noisy
       copy of the target (must PASS the probe criterion); a shuffled-label
       null. Save the outputs with the pre-registration hash.
    P  All four behave as expected; otherwise fix the rule before training.

T2  Training health [now]
    Q  Did each run train, and is it healthy?
    M  Gates G1-G5 (section 4.5); loss curves; effective rank over training.
    P  All gates pass for >= 4 of 5 seeds; failures are reported, not
       dropped.

T3  Invariance and sensitivity [now]
    Q  Does the embedding ignore what it should, and react to what it must?
    M  Retrieval@1 of an event among all events after each augmentation
       separately (should be high). Also apply the FORBIDDEN transforms (sign
       flip, time reversal) and measure the embedding distance: it should be
       large (sensitivity). Compare with morph8 and own init.
    P  Reported per transform; a model invariant to sign flip has lost
       direction information.

T4  Proxy probes, as a regression test only [now]
    Q  Is the model at least as good as before on shape?
    M  kNN and linear probes on polarity, lobe count, log duration, as in M5.
    P  No drop of more than 0.03 vs the M5 SimCLR-TF reference. Not used as
       evidence of success (rule R10).

T5  Label efficiency (PRIMARY test) [labels]
    Q  Does SSL pre-training make vehicle tasks learnable from fewer labels?
    M  For each labelled task: train a linear probe and a small fine-tune on
       10 / 30 / 100 / 300 labels (repeated subsamples, stratified), test on
       held-out days or sessions. Representations: SSL-TF, SSL-CNN, own init,
       untrained CNN, raw, PCA, morph8 (+ amplitude).
       Metrics: balanced accuracy / macro-F1; R2 for speed. Summary: the area
       under the label-efficiency curve.
    P  Pre-register a minimum effect (e.g. +0.05 balanced accuracy at 30 or
       100 labels vs the untrained CNN), with a day-level bootstrap CI that
       excludes 0.

T6  Same-vehicle retrieval [controlled passages, 0D]
    Q  Are passages of the same vehicle closer to each other than to other
       vehicles, across speed, lane and direction?
    M  Recall@1/5 and mean average precision of other passages of the same
       vehicle; stratified by "same speed" vs "different speed" and "same
       lane" vs "different lane".
    P  Reported against morph8, own init and raw. This is the direct test of
       "car model recognition".

T7  Generalisation and robustness [now + labels]
    Q  Does performance hold across runs, days, SNR and conditions?
    M  Leave-one-run-out and leave-one-day-out; results by SNR band
       (20-30, 30-100, > 100), time of day, weekday/weekend, polarity group.
       Synthetic stress: add real background noise to reach lower SNR;
       insert dropout gaps; shift the crop by +-1 s.
    P  Report per group; flag any group more than 0.10 below the mean.

T8  Leakage / nuisance (critical for federation) [now]
    Q  Does the embedding encode the client (run, day, hour) or the
       recording environment beyond what physics explains?
    M  In a single space: is-0204, date, hour bin, run excluding 0204, and
       log noise-floor sigma. Probes: logistic regression AND kNN (HGB if
       affordable); report the strongest. Conditional version: skill of
       [embedding + morph8] minus morph8 alone. Calibrate with a day-level
       permutation null (>= 100 permutations).
    P  SSL minus own init <= +0.05, and inside the permutation null's 95th
       percentile.

T9  Baselines and nulls [now]
    Q  Is any gain more than what a trivial objective would give?
    M  Besides own init, raw, PCA and morph8:
         - SSL trained on phase-randomised events (same power spectrum, no
           shape): the "trivial invariance" null;
         - an encoder trained with supervision to predict morph8: an upper
           reference for what the architecture can extract.
    P  The real SSL model must beat the phase-randomised null on T5 or T6.

T10 Ablations [now for proxies, labels for conclusions]
    One factor at a time, 3-5 seeds each, scored on T5/T6 (or T4 until
    labels exist):
      - leave-one-augmentation-out; stretch range 0 / 0.95-1.05 / 0.85-1.18;
      - input: shape only vs + amplitude vs + morph8;
      - pre-training data: 25 / 50 / 100 % of SNR >= 20, + SNR 5-20 with
        blip filter (a data-scaling curve);
      - transformer patch size 0.5 / 0.2 / 0.1 s;
      - training length 1k / 3k / 10k / 30k steps (a learning curve);
      - objective: SimCLR vs VICReg.

T11 Statistics (applies to all of the above)
    - Unit of resampling: day, then 30-minute block (or session for 0C/0D).
    - >= 8 held-out days for the final test (M5 had 4, forcing a win on all
      4 days).
    - Holm correction within a small, pre-declared family (SSL vs untrained
      CNN, SSL vs own init, SSL-TF vs SSL-CNN). Everything else descriptive.
    - Report effect sizes with 95 % CIs and per-day values, not only p.
    - Paired comparisons (same events, same seeds).

T12 Federated readiness [after T5-T8]
    Q  Will this encoder survive training across clients?
    M  Simulate federation centrally: clients = days (or runs), FedAvg and
       FedProx, IID vs non-IID splits, global normalisation. Compare with the
       central model on T4/T5, and repeat T8 on the federated model.
    P  Federated within a pre-stated margin of central (e.g. 0.03) with no
       increase in client leakage.
