# External audit: research/model/M4_methods

## Verdict
ACCEPT WITH FIXES. The pre-registration is mostly rigorous, but it has internal inconsistencies, a validation/test overlap, a statistical design that cannot support some of its own claims, and several unspecified details. Fix these before any training. Only PREREG.md was provided, so there is no M4 code or results to audit.

## Issues
1. [BLOCKER] Data split: Feb 26 (run 0224) is validation, and Feb 25 (run 0224) is a test day. They are adjacent days of the same run. Validation-based selection therefore sits next to test data, and adjacent-day events and background noise are highly correlated. The statement "never used for tuning or selection" is weakened. -> Move validation to a day not adjacent to a test day, or state and quantify the adjacency risk. Also confirm that the Feb 26 background pool exclusion is enforced in code.
2. [MAJOR] Selection rule: only 2 grid cells per method, seed 0 only, and a single-seed validation score decides the cell. The gap between the two cells will often be within seed noise. The kNN-only selection also favours kNN-friendly embeddings, while the final comparison needs both probes. -> Report the validation gap and seed noise. Predefine a tie-break rule. Alternatively use the mean over 2 seeds for selection.
3. [MAJOR] Equal tuning budget is not equal. Each method gets 2 cells, but the grids vary different things (T, lr, mask ratio). M2's λ/μ/ν and expander are untuned and fixed from the literature. M3 uses a linear decoder and only the crop augmentation. The CNN gets no lr or architecture tuning. -> State this as a limitation in the conclusions, or tune the most sensitive hyperparameter for each method.
4. [MAJOR] Statistics: the bootstrap resamples 5 seeds with replacement, so a CI over 5 seeds is unstable. Each resample draws test blocks from only 4 days, a small number of clusters. Drawing the seeds independently for A and B in a pair is unspecified. The Holm correction over 18 comparisons with a ≥0.02 effect-size rule is stated per probe, but how the two probes' decisions are combined is unclear. -> Specify the pairing of seeds and blocks (paired blocks, independent seed draws). Report the number of blocks per day and flag that the CI is conservative or anti-conservative.
5. [MAJOR] Kernel/probe details: "logistic regression (L2, C=1) or ridge (α by inner CV)" leaves the choice open, and the choice can change results. Duration R² is ambiguous about which probe applies, and the kNN regression variant is not defined. Chance-corrected balanced accuracy is not defined for multi-class (S2, capped at 4) versus binary. -> Fix one linear probe per score. Define the chance correction formula exactly, e.g. (BA − 1/K)/(1 − 1/K). Define the lobe-count labels and the polarity labels precisely, including which source they come from. They are morph-derived, so the probes partly measure morph8 recovery.
6. [MAJOR] CV design: 5-fold CV grouped by 30-min block is pooled across 4 test days. Adjacent blocks are autocorrelated, and neighbouring events from overlapping or adjacent blocks can leak between folds. Training-day events are not used for the probes at all, so the probe is trained on test-day events only. This is acceptable, but should be stated. -> Use contiguous or larger blocks. Consider fitting the probe on training days and evaluating on test days, which also tests the in-distribution claim.
7. [MAJOR] Leakage criterion: "≤ own init + 0.05" is not calibrated. The init baseline for is-0204 skill may already be near ceiling or noisy. Test-day identity is measured on test events only, while the leakage embedding covers all events, an unclear class definition. The higher of two probes is used (max over probes inflates false flags). The class balance of is-0204 (one day against the rest) is unspecified. -> Provide the init values and a seed-based CI. Define the class sets and the training/CV split for the leakage probes.
8. [MAJOR] Dry run: it covers only the scorer, not the training pipeline, as the "planted-control dry run before training" claim implies. It is also thin: morph8 polarity ≥0.90 is circular, since polarity is derived from the same morph features. It does not test duration or lobe count. It has no positive control for R² > 0 on duration. -> Add a planted embedding for S2 and S3 (e.g. a noisy copy of the labels). Add a pipeline smoke test showing training reduces loss and an overfit sanity check.
9. [MINOR] Primary scores: SNR ≥ 20 targets are morph-derived (m8_dur10, polarity, lobes). The same constructs are used for evaluation and training augmentations (stretch changes duration, and amplitude/polarity augmentation could affect polarity). Augmentation invariance versus the probed targets is unaddressed: if phase F's augmentations include polarity flips or time stretch, S1 and S3 are suppressed by design for M1, M2 and M4 and not for M3. -> List the augmentations and check which probed attributes they perturb. State the asymmetry.
10. [MINOR] M3 design: "same transformer encoder" with mask tokens means that at test time the input is unmasked, a train/test distribution shift. Pooling and the embedding head for M3 (no projection to 64 dims) are undefined, so the embedding dimension is not matched. Per-event max-normalised input makes the MSE scale-dependent. -> Specify the M3 embedding (pooling, dimension, whether a projection is used). Specify the normalisation and the patch size (0.5 s at 50 Hz = 25 samples; 12 s/0.5 s = 24 patches).
11. [MINOR] Learning-check and ranking rules: pairwise wins minus losses with the 0.02 gap and both-probe agreement leaves a likely outcome of mostly "no clear difference". Nothing is said about what is concluded then. The "not learning" verdict uses the same Holm family or a different one, unspecified. -> State the decision rule for the Holm family in the learning check and the intended interpretation of an all-ties result.
12. [MINOR] Reproducibility and consistency with other workstreams: the SNR ≥ 20 count in E is 4 375 over 14 days. The test set is about 4 days, so roughly 1 250 events, over ~100 blocks, which limits power for the 0.02 gap. The 873 excluded events in run 0204 (mask_frac) leave test day Feb 7 underrepresented. The time basis is fs_local (A/E), and the earlier note about legacy int16 wrap does not apply here, but the data path should be the extraction store, which should be stated. No seeds are fixed for data order, augmentation or the bootstrap beyond seed 0. -> Report the per-day test event counts up front. Fix seeds for augmentation and init. Pin the commit hash and the event list.
