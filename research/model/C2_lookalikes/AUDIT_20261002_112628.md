# External audit: research/model/C2_lookalikes

_20261002_112628 · served by claude-sonnet-5-5 · effort medium · 11492 in / 2654 out · ~$0.050_

## Verdict
ACCEPT WITH FIXES: the pre-registration is mostly coherent and well-structured. However, only the PREREG was submitted, with no code, results or REPORT. Several design flaws would bias the decision rules, and the 600-sample crop definition is inconsistent with the rest of the pipeline.

## Issues

1. [MAJOR] PREREG, Validation/R: LORO reproducibility is not independent of the grouping. Transfer assigns a B event to the nearest A medoid only if d ≤ 1. Grouping B directly with complete linkage and cut at 1 gives different group structure from medoid assignment. `ari_joint` is computed only on events that are grouped in both, and `frac_joint` is gated at 0.30. A method that finds a few tight, easy groups can score high ARI on a small joint set. -> Report ARI against a size-matched random-medoid baseline. Also report the number of groups and events in the joint set per fold. Add a minimum joint-set size to the decision rule.

2. [MAJOR] PREREG, Null: the phase-randomised null destroys shape correlation but keeps amplitude and duration. The null tests only "correlation ≥ 0.90 is rare among random-phase waveforms", not whether groups exceed what is expected from real events of non-vehicle origin. Phase-randomised waveforms also have a flat, Gaussian-like envelope, so the null is too easy. The "≤10 % of real count" threshold is therefore weak. -> Add a harder null: shuffled real events, or time-reversed/sign-flipped events with matched amplitude spectra. Also add noise-only windows. Report group sizes, not only counts.

3. [MAJOR] PREREG, Status/Decision rules: the C1 collapse rule was written knowing that seeds 2 and 4 collapse, and the thresholds (50 %, 5 clusters) were chosen post hoc. The reliability thresholds (0.50, 0.30, 0.30) have no stated justification. The preference "C2b must beat C2a" therefore rests on a tuned filter. -> State this as a limitation in the REPORT, and run C2b with all seeds as a sensitivity check. Do not call the verdict confirmatory.

4. [MAJOR] PREREG, C2a: complete-linkage on d requires an n×n distance matrix. With ~4.4k events at SNR ≥ 20 this is fine, but the unstated event set is a problem. The prereg never says which tier is used (SNR ≥ 20 or 30, run 0204 excluded or not). C's clean tier is biased toward high-SNR, large, morning events, and the E report finds blip contamination at SNR < 20. Coverage and group results depend on this choice. -> Fix the event set before running, and report results on both SNR tiers.

5. [MAJOR] PREREG, shape definition: correlation is computed on a 600-sample, 50 Hz crop, i.e. 12 s, in counts, with ±1 s shift. E defines the central crop (m8) as 402 samples, ≈ 8 s. The two crops are inconsistent. Pearson correlation on raw counts is dominated by the largest lobe, so it is sensitive to the crop length and to the sign of long tails. For events of 0.05–10 s duration, a 12 s crop means correlation is mostly baseline noise for short events. Duration clipping at 0.05 s is also far below the 0.3 s minimum event length that C drops. -> Justify the crop length. Report sensitivity with the 402-sample crop. Clip durations at ≥ 0.3 s. State the sign convention (polarity), and whether |corr| is used.

6. [MAJOR] PREREG, amplitude/duration constraint: the SSL consensus (C2b) can only remove pairs from C2a. The refinement then applies the same d. So C2b is a subset or refinement of C2a groups by construction. "SSL helps" is then only the claim that SSL pre-partitioning improves LORO ARI. It could equally reflect the ≥ 10 size filter applied twice, or merely less coverage. -> Add a control: C2a with a random pre-partition of matched coverage. Compare at matched coverage, not by ARI alone.

7. [MINOR] PREREG, LORO for C2b: only seeds 0, 1 and 3 are retrained, chosen because those are the non-collapsed seeds, so seed selection uses the knowledge of C1 outcomes. A fold may collapse in a way that excludes all kept seeds, and no rule is stated for that. The odd/even split reuses C1 models trained on all days, so it leaks. -> Define the fallback (fold fails reliability), and state that odd/even is not evidence.

8. [MINOR] PREREG, Dry run: the synthetic set uses the same 5 real templates and U(0.8, 1.25) amplitude, which are tuned to the tolerance. Passing says the algorithm works on the easy case; it does not validate the tolerance. The template ARI ≥ 0.70 threshold is only a modest check. The SNR range 20–300 may not match the real distribution. -> Add a harder dry run with realistic SNR (20–40) and timing shifts. Also report per-template recall.

9. [MINOR] PREREG, Tolerance: max-norm of three normalised terms means d is dominated by whichever is worst. Group tightness for amplitude and duration is guaranteed only pairwise. Report within-group spread via p90/p10 (stated, good). The strict and loose sensitivity settings are reported without a decision rule. Group-count stability across tolerances is not assessed. -> State how sensitivity results affect the verdict (for example, count groups at each tolerance).

10. [MINOR] PREREG, Deliverables/reproducibility: no seeds are given for the 10 null draws, HDBSCAN parameters or random-group gallery. The prereg does not state that the Time/fs conventions from A are used (fs_eff 49.82–50.11 Hz rather than exactly 50 Hz), so the "1 s" shift and the 600-sample duration are only approximate. -> Fix the seeds and HDBSCAN parameters, and use fs_eff for the shift conversion.

11. [MINOR] PREREG, Not claimed: "events without a group are unique within this dataset" is itself a claim. Run 0204 has more dropouts and short blips, and groups made of the same blip population would be artefactual. -> Report the group composition by run, hour and dropout status (confound leakage, as D did), and flag groups dominated by one run.
