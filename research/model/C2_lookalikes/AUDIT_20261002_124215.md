# External audit: research/model/C2_lookalikes

_20261002_124215 · served by claude-sonnet-5-5 · effort medium · 34571 in / 2371 out · ~$0.093_

## Verdict
ACCEPT WITH FIXES. The C2a result (tight groups exist, boundaries do not reproduce across runs) is largely supported. Several C2b and "SSL helps" claims are hollow or mis-specified, and a few statistics and code paths need correcting before the report can be trusted as written.

## Issues
1. [MAJOR] results.json / REPORT: `ssl_helps: true` is retained in the output even though the report calls it hollow. The control used a matched-coverage pre-partition with coverage 0.004, which is not a matched control (it was meant to match C2b's consensus coverage). The E5a claim test was therefore passed vacuously. -> Delete or invert the flag, or fix the control. The control's `rand_pre` is built from `sizes*k` with `int` truncation, which drops small groups. The refine step on random partitions of non-look-alikes yields almost nothing by construction. A proper control would randomise the SSL cluster assignment within strata of amplitude and duration.
2. [MAJOR] c2.py `run()`, C2b LORO: seeds 0, 1 and 3 are selected after seeing the C1 collapse. Folds then use `len(kept)<2 → ARI 0`, and this fires in 3 of 4 folds (the B side keeps 1 seed). The resulting mean ARI of 0.08 measures HDBSCAN collapse, not what SSL can do. The verdict "SSL does not help" is mostly untested rather than negative. -> Describe C2b as inconclusive, not as "no evidence it helps". Or tune the fold training (mcs, steps) and rerun, treating that as a new pre-registration.
3. [MAJOR] c2.py `compare`/`repro`: the LORO transfer is asymmetric. Group B is clustered independently on the held-out run, and A's medoids are used for transfer with a hard d≤1 cut. Events of B that lie in a continuum are given different cuts, so the low `frac_joint` (0.11–0.27) and ARI of 0.38 are largely an artefact of complete linkage on a different sample size. The cutoff is also data-size dependent. -> Add a non-partition reproducibility measure, e.g. the fraction of B events whose look-alike neighbourhood in A overlaps, or a pairwise agreement rate. Otherwise "not partitionable" is overclaimed, since it is conditional on the specific algorithm.
4. [MAJOR] REPORT, "88 % of events have at least one look-alike, median 89": this is not in results.json. The same applies to the "78 % have ≥10" figure and the "worst-case 1.494/1.490/0.900" verification. -> Add a script and an output that produce these numbers, or remove the claims. The independent verification is not traceable.
5. [MAJOR] PREREG: the decision rules were not changed, but the dry run was modified after failure (F1). The new main dry-run amplitude (×0.9–1.11) is chosen to pass. Under the original sweep, ARI is 0.58. The SNR 20–40 variant (0.73) barely passes and has template-5 recall of 0.57. -> Report the dry-run PASS as conditional on the amended specification. Note the 'amp0.8_1.25' entry in dryrun.json equals the failed v2 result.
6. [MINOR] c2.py `dryrun`: synth uses `rng(1)` for the data, not `default_rng(2)` as E7 states, and the `rng` instance in `dryrun` is only used for the null. The seeds do not match the pre-registration. -> Correct the pre-registration text or the code.
7. [MINOR] c2.py `feats`/`dryrun`: the dry run computes amplitude and duration from `morph_feats` on the central 8 s crop of a synthetic event, while the real run uses the stored `m8_*` features. The features can differ in definition (e.g. polarity and amplitude units), so the dry run is not an exact rehearsal. -> Check that the two paths agree on real events.
8. [MINOR] c2.py `consensus`: `lab[noise_majority] = -1` is applied after fcluster, but the co-association counts a pair only if both are non-noise in the same seed. An event that is noise in most seeds gets a distance of 1 to all others and becomes its own cluster anyway. This is harmless but redundant. A more important point: the co-association matrix is n×n float32 (35k², ~5 GB), which exceeds the 10 GB budget when D, P and the copies are held concurrently. -> Report the peak RSS.
9. [MINOR] REPORT: the time-reversal null is described as "many prints are nearly time-symmetric", but the corrected measure only mixes groups, not counts of paired events. Only the group count is used. The `Xr` aligned correlation is also run with `chunk=8`, which is not documented. -> Describe it as descriptive only and drop the interpretation.
10. [MINOR] REPORT, galleries: "visually convincing" is a subjective claim by the orchestrator, and the galleries show only up to 40 members. -> Quantify, or soften.
11. [MINOR] Sample: all analysis uses the SNR≥20 subset, which workstream C noted is biased toward high-SNR, large, morning events. 4 375 events over 14 days. Dominant groups sit at hour_median 9, so "look-alike" density is about morning-peak traffic. Coverage generalises poorly. -> State this limit in the verdict.
12. [MINOR] Statistics: no confidence intervals on ARI, with n_joint as low as 90 and only 4 folds. The thresholds 0.50 and 0.30 are conventional, not derived. -> Add bootstrap CIs.
