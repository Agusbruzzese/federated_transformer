# External audit: research/model/C1_clustering

_20261002_102430 · served by claude-sonnet-5-5 · effort medium · 11289 in / 2226 out · ~$0.045_

## Verdict
**ACCEPT WITH FIXES.** The pre-registration is a reasonable and mostly well-structured plan. Several decision rules are circular, under-specified, or mismatched to the data, and the brief itself does not define a C1 workstream. These need fixing before any result is called "valid". Only the PREREG was supplied, so no results, code or REPORT could be audited.

## Issues
1. [MAJOR] PREREG, Reference similarity: the AWD is both the "definition" of similarity and the R1 representation being validated. V1 (aligned correlation) is nearly the same quantity as AWD, so R1 passes V1 by construction. R1 is also favoured in the V2 and V4 comparisons. -> Treat AWD as the reference for R2 and R3 only. For R1, report V1 as non-independent, and use independent checks (amplitude CV, duration CV, V2).
2. [MAJOR] PREREG, V1 thresholds: aligned correlation ≥ 0.80 is computed on which signal, raw counts or log-compressed? The ±1 s shift search maximises correlation, so a random grouping also scores high on smooth, unimodal events. The null is applied only to the CV tests and not to the correlation. -> Specify the signal and the correlation definition (shift range, max vs fixed). Add the random-grouping baseline for correlation and require the cluster value to exceed its 95th percentile.
3. [MAJOR] PREREG, Data/V2: "no held-out test set", and SSL is trained on all events, including the events later clustered. Split-half by odd and even days still sees both halves during SSL training, so R2's V2 and V3 are optimistic relative to R1 and R3. Odd/even days also mix weekday and weekend and are not independent, since the same sensor, runs and traffic are shared. -> Train SSL on one half only for V2, or flag R2's V2 as leaky. Add leave-one-run-out as a stricter reproducibility check.
4. [MAJOR] PREREG, Data/R2: the SNR ≥ 20 selection is an amplitude-selected, biased subset (C: the clean tier is biased to high-SNR, large, morning events). Clusters may reflect SNR and amplitude strata, not "similar signatures". -> Report cluster purity against SNR, amplitude and hour. Add a confound-leakage check as D did (date, run and hour predictability from cluster labels).
5. [MAJOR] PREREG, R2: z-scored log amplitude and duration are appended to the embedding, and these are the same scale variables used in V1's amplitude and duration CV tests. Clustering on them and then testing tightness in them is circular. -> Evaluate V1 on variables not used for clustering, or acknowledge the bias and compare R3, which also contains them (m8_dur10).
6. [MAJOR] PREREG, Decision rules: "valid" requires V4 < half as many clusters as the real data, which is weak (a null with 1 vs a real 2 passes). Rules say nothing about the number or coverage of clusters (V5 is reported but has no decision role). One giant cluster, or 5 % coverage, could be "valid". -> Add a minimum coverage and a maximum single-cluster share, and require V4 ≤ 1 cluster as in the dry run.
7. [MINOR] PREREG, V2: ARI is computed only on events clustered in both halves, which inflates agreement when noise is large. Nearest-neighbour label transfer is biased toward dense regions. -> Report the ARI including noise as a class, and the fraction of events excluded.
8. [MINOR] PREREG, V4: the null for R1 (phase-randomised waveforms) destroys shape but keeps the spectrum and amplitude, so it tests something different from the column-permuted nulls of R2 and R3. Permuting every column independently of R2/R3 destroys the correlation structure and is an easy null. -> Add a harder null, such as events shuffled in time with their scale preserved.
9. [MINOR] PREREG, Clustering: HDBSCAN with "default min_samples" on 10-d (R2) versus a precomputed 4375² (R1) matrix. The sensitivity at 10 and 25 is not used in any decision. -> State whether the sensitivity affects the verdict. Fix random seeds and the PCA dimension (8), and justify it.
10. [MINOR] PREREG, AWD: σ₀ = 100 counts is asserted, and log compression changes what "similar amplitude" means (it compresses large amplitude differences). The ±1 s shift limit and duration differences at 12 s crops with no length normalisation are unaddressed. -> Check the sensitivity to σ₀, and add a duration-specific check on the crop.
11. [MINOR] Brief coverage/consistency: the orchestrator brief does not include C1. The PREREG uses 4 375 events and 50 Hz crops consistent with E, but no spec for the "central 12 s" window (E windows are 21 s; the 402-sample crop is about 8 s). -> Define the 12 s crop (600 samples) explicitly and its handling of overlapping events and masked dropouts.
12. [MINOR] Dry run: the planted templates, amplitude ±10 % and shift ±0.3 s are easy and do not test amplitude-variation or overlapping vehicles. The ARI ≥ 0.80 target is only for R1 and "R3-style". R2 is not dry-run. -> Add a harder planted case (SNR spread, overlaps) and dry-run R2.
