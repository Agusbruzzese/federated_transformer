      recomputed.

    - The evaluator's formulas match report 09 sections 5-6.

  Required before freezing (orchestrator re-checked the two code claims
  marked *):
  R1  MAJOR-1*  The arm definitions exist only in a test file, and the CLI
                defaults are unsafe: --arm server with the default rounds
                gives 409 600 examples instead of 423 936 (recomputed);
                --arm central defaults to batch 64. Fix: a frozen
                manifest.json (one entry per arm x fold x seed, full CLI,
                tag, server checkpoint) and launch.py, which runs only
                manifest entries and checks budget, K, batch, rounds and
                init hash before training.
  R2  MAJOR-2*  The decision procedure exists only as building blocks.
                Missing:
                  - assembling the seed x 9-day grid with keys;
                  - Zbar;
                  - the Q-S rule;
                  - the attribution rules;
                  - the collapse rule (effective rank not computed);
                  - sensitivity analyses (a)-(d);
                  - tuning scoring on Feb 10.
                Unspecified: the interaction CI and the seed-paired
                formula. Silent risk: misaligned day columns change the SE
                with no error (orchestrator's toy test: SE 0.0101 ->
                0.0120, no exception). Also, score() does not check which
                fold a checkpoint was trained on.
                Fix: analyze.py and tune.py with unit tests (a misaligned
                input must raise; toy data must give known labels), a fold
                assertion in score(), and both formulas written into the
                amendment.
  R3  MAJOR-3   N_SEEDS = 10 makes the controls inconsistent: C1, C4, C5,
                L1, L2, the m_leak rule and the noise floor were defined on
                seeds 0-4 vs 5-9, which are now all main seeds, and they
                would be calibrated at n = 5 while decisions are made at
                n = 10.
                Recommended: train C256 seeds 10-19 x 3 folds as a replicate
                reference (30 runs, about 1.6 h GPU) and run every control
                at 10 vs 10:
                  C1 C256(10-19) vs C256(0-9) EQUIVALENT
                  C3 init(0-9) vs C256(0-9) INFERIOR
                  C4/C5 on C256(10-19)
                  m_leak from 10 vs 10
                  L1/L2 on the same pair
                  noise floor = seed pairs (s, s+10)
                Cheaper alternative: split-half 0-4 vs 5-9, labelled as an
                n = 5 calibration (lenient m_leak).
  R4  MINOR     - wrong file names in report 09 (fedsim.py / test_fedavg.py
                  -> fedsim2.py / test_fedsim2.py);
                - folds.py opens folds.json in "w" mode (must never be
                  rerun as is);
                - L1 is not "PASS by construction" (false-FAIL risk about
                  0 at the measured Z spread; decide the response in
                  advance);
                - L2 needs an operational definition (kappa* = smallest
                  kappa detected in >= 50 % of seed-folds; the gate must
                  FAIL at kappa*);
                - learning-rate trace not logged;
                - provenance: test outputs lack code hashes, the pool hash
                  is not asserted before training, the guard is name-based,
                  the final checkpoint hash is not stored;
                - assert >= 2 classes per day in skill;
                - gate fit convergence not checked;
                - docstring fix;
                - state that the IID permutation is fixed across seeds;
                - keep the fold-correlation caveat for the day stratum.

4. ASSESSMENT
  The review found no design or implementation error in what exists: the
  simulator and the statistics are correct and proven. What is missing is
  (i) code that removes human choices from launching and analysing (R1,
  R2), and (ii) a control design matched to the user's 10-seed decision
  (R3). Both are needed so that the freeze actually fixes every decision
  in advance. Freezing now would leave the analysis to be written after the
  data exist.
