## Issues
1. [BLOCKER] Workstream `model`: no REPORT.md, code, seeds, embeddings or numbers are supplied. The briefs only cover A–D, so the phase F brief is also absent. -> Supply the actual work, or confine the audit to the pre-registration. No quantitative claim can be assessed at present.
2. [MAJOR] PREREG Data split: Run 3 is described as "weakly held out" because C viewed it during exploration. C's detector thresholds (5σ/2σ, SNR≥30 cut) and the SNR≥20 tier were tuned or chosen with that knowledge. Event selection, the L=21 s window and the 20 and 30 SNR cuts all inherit that exposure. -> Quantify and state the exposure. Treat the Run 3 results as exploratory, or add a truly unseen split, for example Run 4's last day. Note that Feb 26 is already used for validation.
3. [MAJOR] PREREG Data split: Run 3 is the only holdout, and it covers 3 days (Feb 18–20). "Cluster bootstrap by day" with about 3 clusters gives very unreliable CIs. A 3-day holdout also has a narrow range of hours and weekdays. -> Use block bootstrap by chunk block with many more clusters, or leave-one-day-out over all days. Report the number of clusters and state the low power.
4. [MAJOR] PREREG P1: the "CIs excluding 0 for the difference" criterion applies to 3 of 4 targets, with no multiplicity control and no test of the 3 seeds against the random-init CNN. Polarity and n_lobes are not defined in the pre-registration. They depend on the C and B detector and on the morphology scalars. -> Define the targets and the estimators, including the R² and skill formulas. Say how seed variance enters the CI.
5. [MAJOR] PREREG P1 circularity: log_amp is not given to the encoder, but the input is max-normalised per event. Amplitude could still leak through noise-floor shape, relative SNR and the SNR-matched noise augmentation. Training on SNR≥20 events also restricts the amplitude range. Duration is partly fixed by the C segmentation. The 19 morphology scalars (baseline a) include amplitude and duration features, so they predict these targets trivially. -> Report the probe against the morphology baseline as well. Check the predictability of amplitude from the SNR alone.
6. [MAJOR] PREREG P2: the thresholds are arbitrary ("baseline + 0.05", "has_dropout ≤ 0.2"). Date and run skill on a holdout of one run and 3 days is undefined: run is constant, so run prediction cannot be evaluated inside Run 3. -> Define the leakage evaluation over train and validation runs, or use grouped CV across all runs. Fix the skill definition (chance-corrected?).
7. [MAJOR] PREREG P3: retrieval@1 of an event's augmented view measures augmentation invariance, which is exactly the SSL training objective. PCA and the untrained CNN are not optimised for it, so "beats baselines" is nearly guaranteed and uninformative. It also uses forbidden augmentations only partially. -> Demote P3 from the headline, or add a non-trivial comparator such as augmentation-matched handcrafted features. Use held-out augmentation types.
8. [MAJOR] PREREG Headline: "positive verdict" requires P1 and P3 and P2. P4 and P5 are secondary. The CNN vs Transformer comparison has no matched-compute or tuning budget, and there is no hyperparameter protocol. Validation on a single day, Feb 26, is the only model-selection signal, and no selection criterion is given (loss? probe?). -> Specify the selection metric, epochs, the LR and other hyperparameter budgets, and equal tuning for both architectures.
9. [MAJOR] PREREG Augmentations and cross-workstream consistency: the SSL pairs come from the same event, but adjacent overlapping events, and events close in time, are not excluded from the negatives. The fixed 21 s window crop of 12 s assumes L=21 s, valid only for C's clean tier, while the training tier is SNR≥20 (5.5k events versus 4.1k clean). Time-stretch 0.85–1.18 combined with the ±0.3 % fs uncertainty is fine, but A's dropouts (0.5 % of slots, 1 % in run 0204) must be repaired or masked, and the PREREG says nothing about it. P2 `has_dropout` is acknowledged as a leak but no handling is specified. -> State how dropouts and overlaps are handled, and the filtering and decimation from B and D. Specify that the input is the correct 24-bit data (D1: the legacy reader wrapped at 16 bits) and the fs_local time base.
10. [MINOR] PREREG P4: Jaccard ≥ 0.3 at k=10 is arbitrary, and the random-init CNN may already pass it. Neighbourhood consistency across seeds is also inflated by hubness and by the dominant amplitude structure. -> Add the null (shuffled) value.
11. [MINOR] PREREG P5: the phase-randomised null is under-specified. Phase randomisation destroys the event morphology, so the null is trivially different. -> Use a correlation-preserving but morphology-matched null, or drop P5.
12. [MINOR] PREREG Human labels: the 80-item pack is the AI's own judgement (C correction 1), not human labels. The V vs N check is therefore not external. -> Relabel it as "AI-annotated" or obtain human review.
13. [MINOR] PREREG: "may not be edited once training starts" is unenforced. -> Commit-hash it and record the hash in the report.
