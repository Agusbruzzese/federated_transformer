## Issues

1. [BLOCKER] F_central/REPORT §0, §8: The headline verdict "Positive" for both models is not supported by the evidence in the same report.
   - log_amp is matched or beaten by SNR alone (Δ −0.031 / −0.051).
   - The CNN's log_dur is significantly worse than random-init.
   - Both models sit below morph8 on every target.
   - Date and run skill pass only because the threshold is morph8 + 0.05 (0.068 / 0.172), a loose tolerance the PREREG itself calls "conventions, not derived". -> Report the verdict as "weak/partial". Don't present "Positive" in the summary table without the qualifiers.

2. [MAJOR] P2 criteria in PREREG v2: has_dropout ≤ 0.2 could not fail; the CNN's 0.077 equals its own permutation null (0.074 ± 0.015). The null is non-zero, which suggests the permutation is not a clean chance baseline for has_dropout (a day-grouped permutation preserves day prevalence). -> Explain the non-zero null. v3 fixes this within run 0204 only; it must actually be run.

3. [MAJOR] Run 0204 identifiability: SSL training roughly doubles is-0204 skill (CNN 0.083→0.165, transformer 0.025→0.113), which is leakage that the pre-registered P2 date/run test does not catch. The "passes P2 without leaking" interpretation is overstated. -> P2c in v3 is the right fix. Until it is run, say "leaks run 0204".

4. [MAJOR] F_central/REPORT §6: The p-value, one-sided p = (1 + #{Δ* ≤ 0})/1001, is resampled over blocks only. It ignores the 3-seed variation (seed SD of Δ up to 0.077 for transformer polarity random-init). Three seeds make the random-init baseline unstable, e.g. the transformer random-init log_amp of 0.513 vs 0.385 on validation. -> The v3 move to 5 seeds is right. State that the F p-values understate uncertainty.

5. [MAJOR] Selection and holdout: selection used one validation day (366 events) with grid means spanning only 0.587–0.639, and the CNN/transformer choice is within noise. The holdout is "weakly held out", and a single run is used. v3 mitigates this with LORO, but F's verdicts are still stated with confidence. -> Label selected hyperparameters as arbitrary within noise.

6. [MAJOR] Post-hoc evaluation edits (deviation 2): the evaluation code was changed after some results were seen. Only config.py is hashed; evaluate.py and probes.py were not, so "no criterion changed" is unverifiable. -> v3 logs hashes of all files. Say that F's claim is unverifiable.

7. [MAJOR] Secondary-tier P2 was run with 2 and 5 permutations, and the all-SNR tier has early stopping active. The all-SNR "Positive" verdicts are printed in the JSON despite substantial leakage (date 0.14, run 0.20, is-0204 0.46). -> Remove the verdict labels from the secondary tiers. v3 already makes them descriptive only.

8. [MINOR] P1 target circularity: morph8 "ceiling" contains the targets (polarity skill 1.000). The block bootstrap with 93 blocks of skewed size (max 75 events) gives wide CIs. kNN with z-scored features penalises PCA (acknowledged), so the "SSL beats PCA" claim is weak.
