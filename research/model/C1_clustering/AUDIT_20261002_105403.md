## Verdict
**ACCEPT WITH FIXES.** The pre-registration is mostly sound and stricter than it started, but several validity criteria are circular or weak, the dry run was tuned after a failure, and no REPORT.md or results.json was supplied. As a result, no verdict can be checked against the pre-registered rules.

## Issues
1. [BLOCKER] Deliverables: `REPORT.md` and `results.json` were not provided (the results file was omitted as too large). The brief requires a report with hypotheses, quantification, confidence per finding and the pre-registered verdict. -> Provide REPORT.md stating each validity check per representation, the `recommended` value, and the confidence level. Include a deviations list.

2. [MAJOR] c1.py `tightness` (V1 null): the null permutes labels only among clustered events (`rng.permutation(lab[cl])`). That is a fair size-matched null. But the "valid" cut compares `corr` against the null p95 and also requires a fixed 0.80. Amplitude is a strong driver of aligned correlation because the signals are not normalised. The amplitude-matched control is reported but not decisive. -> Make the amplitude-matched p95 decisive, or state that "valid" may mean only "amplitude and polarity bins".

3. [MAJOR] c1.py `aligned(mode="corr")`: Pearson correlation is taken on raw counts over a 12 s crop, and the max is taken over only 101 lags. For R1 this is circular (D1 admits it). The R3 and R2 CV checks (`cv_amp`, `cv_dur`) are also circular, since amp and dur are inputs. Yet `valid()` includes both as hard gates, so R2 and R3 pass them almost by construction. -> Drop the circular checks from the gate, or replace them with measures on variables not used in the representation. Report which checks are independent.

4. [MAJOR] `dryrun`: the D9 failure was followed by a redesign (D10) after a peek (a pre-check was disclosed). Templates are real events and singletons are phase-randomised real events, which are easy to separate from real repeats. R3 uses `morph_feats` on 50 Hz crops, not the stored `m8_*` columns. R2 is never dry-run. PASS therefore says little about the real run. -> Treat the dry run as a smoke test only. Do not cite it as validation of R2 or of the real-data R3.

5. [MAJOR] `split_repro` / `agree`: ARI on jointly clustered events only (`ari_joint`) discards noise-labelled events and is gated. `frac_joint` is reported but not gated. A tiny jointly clustered core can give a high ARI. For R1, `transfer` uses nearest neighbour under the same distance, which favours the metric-defined representation. For R2, SSL was trained on all events (the odd/even split leaks), and the same applies to every LORO fold. -> Gate on `ari_with_noise` or on `frac_joint` ≥ some floor. Retrain SSL excluding the test half or run for the folds, or label R2 reproducibility as optimistic in the verdict.

6. [MAJOR] Leave-one-run-out: run 0204 has the dropout-blip population, and the runs differ in size. The HDBSCAN `min_cluster_size` of 15 is applied to subsets of different sizes, so cluster counts are not comparable. -> Report per-fold values, not only the mean. Scale `min_cluster_size` with n, or justify keeping it fixed.

7. [MAJOR] `V4_null`: R2 and R3 use a Gaussian with the real covariance. With only 10 draws and a ≥ 9 of 10 pass rule, the test is weak. R3's `m8_*` columns include polarity and other non-Gaussian features, so the null is easy to beat. The R1 phase-randomised null destroys shape but keeps amplitude, so it is not matched to the signal. -> Add a block-shuffled or real-feature-marginal null (e.g. a copula) and report the null cluster count distribution.

8. [MINOR] `raw_crops` / `load_all_train`: `m4.load` is monkey-patched and `m4.bgpool` is set to `bgpool.npy` (all days). Training on all SNR≥20 events with a 0 held-out split is fine, but the `bgpool` provenance is not documented. The `pins_at_run.txt` hashes are unexplained. -> Document the hashes and what they pin.

9. [MINOR] `ampmatched`: when a bin has fewer than 400 events the pool excludes cluster members, otherwise it includes them. That is an inconsistent null. A fallback to a random event (`rng.integers(len(lab))`) breaks the matching. -> Always exclude members and report fallback counts.

10. [MINOR] `cluster_profiles.csv`: R1 has only 6 clusters (largest 323 and 263) with 715 of 4375 events covered (about 16%), well below the 30% coverage gate. R1 is therefore invalid by coverage alone. R3 cluster 15 has 1121 events, which is about 1121/3000 > 37%, so it fails the 50% rule only if it exceeds half. Check. -> Report the gate outcomes in REPORT.md. Note that the R3 gallery is dominated by one blob. Hour-of-day medians of 9 for many clusters suggest a rush-hour confound (Cramér's V on hour is only descriptive).

11. [MINOR] `tightness`: `amp[i].std()/amp[i].mean()` with `amp = 10**m8_log_amp` is a CV on a log-normal-like variable, so the mean is dominated by large events. The 5th-percentile null threshold rests on 100 draws. -> Use the CV of log amplitude, or a robust MAD/median, and report an interval.

12. [MINOR] Reproducibility: the global `rng0` is unused. `rng = default_rng(0)` is reused throughout `run()` and so depends on call order. PCA is seeded, and HDBSCAN is deterministic. The data hash is not stated. -> Seed each sub-experiment independently. Record the SSL checkpoint hashes.
