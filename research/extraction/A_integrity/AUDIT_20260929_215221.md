# External audit: research/extraction/A_integrity

_20260929_215221 · served by claude-sonnet-5-5 · effort medium · 69062 in / 2782 out · ~$0.166_

## Verdict
ACCEPT WITH FIXES: the format, dropout and continuity findings are well supported by a full scan. The sampling-rate attribution, several stated confidences, the brief's stratified-value-sanity item and a few report inconsistencies need correction.

## Issues
1. [MAJOR] REPORT §5.4 / F4: The claim that the ADC oscillator itself slows in the daytime rests on assuming the grid is stable, a point the report admits is "general knowledge, not measured". The report also says the mains and PC clock have "slope ≈1". Sample B's CI is [0.91, 1.00] and its point estimate is 0.96. The PC-clock fit and the mains estimate are also not fully independent: mains needs the slot grid, which comes from device ticks. Long-term agreement (0.04 ± 0.15 Hz) supports only the mean, not the diurnal attribution. Sample B covers only run 0204, Feb 4–8, so it cannot support a dataset-wide attribution. -> Downgrade F4 attribution to medium, or compare against public grid-frequency data. Say that the value 2416 Hz is what is established.

2. [MAJOR] F4 uncertainty budget: fs_local ±1.2 Hz is set equal to the whole fs_mains − fs_wall spread. The stated component budget (0.2–0.5 quantisation, ≤0.15 PC clock, ~1 grid wander) is only loosely reconciled with it. The ±0.35 s absolute-time claim is measured on the fit's own training points, and the report admits this. The statement that the filename quantisation is uniform σ = 0.29 s is an assumption. -> Validate the time anchor independently, for example against the Stop@ names or the diurnal traffic onset. Otherwise label ±0.35 s as a lower bound.

3. [MAJOR] F5 / dropout reality: "high" confidence that the missing samples are real lost ADC samples rests on three tests written after the fact (H4 was not pre-registered). The report itself says the hypotheses were not pre-registered. The mains-phase continuity test (c) is listed but no output is shown. Only the value-jump test in rev1 and the flat-rate test are shown. -> Include the phase-continuity output and the jump-vs-lag statistics for the full data, or drop (c) from the claimed evidence.

4. [MAJOR] Brief item A4 (value sanity on a stratified sample): This was replaced by a full scan of spikes, stuck values and range. Sign, clipping and sentinels are covered only by range and by the top-byte check. Sample statistics (σ ≈ 62 counts, ≈18 effective bits) come from 484 chunks and a second-difference MAD, but the "top_missing" subset (100 chunks) was included in the sanity scan. It biases the noise, jump and spike estimates. The report cites 484 chunks without separating random from worst-case. Also, "18 effective bits" is inferred from noise without a full-scale range or any gain calibration. -> Report the noise statistics on the random subset only. Drop or justify the effective-bits number.

5. [MAJOR] §6 / F6: The 3 joins that fall on a dropout are in rev1 but not in rev2. The rev2 claim that contiguity holds rests on `interchunk_slots = max(ic, 1)` in `list_chunks`. That forces every join to ≥1 slot, so any overlap or negative join would be silently hidden. The self-test checks only t_first > t_last, not the join size distribution. The join step distribution is never printed. -> Print the distribution of `interchunk_slots` (unclamped) and the count of joins greater than 1.

6. [MINOR] `slots_from_timestamps`: the strict-monotonic enforcement loop is O(n·k) and can push slots forward silently. It never fires in the tests. The spacing-1 case is dismissed since real min spacing is 4, but that minimum is itself computed with the v2 estimator. The check is circular. The late-only estimator (late samples at burst spacing) is tested only on synthetic data built from the same stamp model, which was measured from only 64 dropout events (postgap_model.csv, 8 chunks per run). -> Measure the post-gap model on more events, especially runs 0212 and 0224, where n is tiny (about 3 to 16 events per size class).

7. [MINOR] `check_ambiguous.py`: it tests only the 40 chunks with the most ambiguous ratios, and only the ambiguous events isolated by >22 samples. 3077 of the 31937 ambiguous events were tested. The conclusion "no hidden 1-sample losses" is generalized to all. It also excludes events near gaps, the very place hidden losses would cluster. -> Say "in isolated events of the worst 40 chunks", or sample randomly.

8. [MINOR] REPORT number inconsistencies: F7 says one spike is in run 0212 #3 during settling, while rev1 says the largest excursion is 783k p-p in run 0212 #15. The spike detector threshold of 20 MAD on the lag-1 difference means real large events are not flagged as glitches. It does not test for genuine artefacts inside events. The self-described "dropped 44.5 ms" also conflicts with ticks not being µs (45.5 ms in ticks is about 44.5 ms real at 1.02). Sample-count totals in the per-day tables use chunk-start dates, and the coverage table uses another attribution. -> Harmonise and state the convention.

9. [MINOR] Reproducibility: hard-coded absolute paths (`DEFAULT_ROOT`, `ROOT`). The `list_chunks` index depends on `full_scan_chunks.parquet`, so run order matters. `list_chunks` caches the index, so the self-test passes against a stale cache. Only some scripts have fixed seeds: `synthetic_slot_test.py` uses the seed 2026, but `measure_postgap.py` uses `random_state` alone. The `mains_check_v2.py` long-term block uses `r0` columns (`slot_start`, `fn_start`) that come from the index, so it depends on the cache. -> Add a checksum or version to the cache and make the paths configurable.

10. [MINOR] Coverage: "10 full days" includes Feb 5–10 (6 days) and Feb 13, 19, 25, 26. Weekend data exists only on Feb 8–9 and is inside degraded run 0204. The recommendation that other workstreams "evaluate separately" is correct but the weekday/weekend confound is not quantified. Day and night comparison of drift uses a 10–17 h "day" window chosen post hoc.
