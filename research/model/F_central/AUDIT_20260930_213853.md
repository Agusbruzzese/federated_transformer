## Verdict
ACCEPT WITH FIXES. The pipeline is executed and reported in detail, but the headline "Positive" verdict rests on loose pass criteria, a baseline comparison that contradicts the stated interpretation, and several self-declared deviations. Without the fixes below, the "SSL learns shape structure" claim is overstated.

## Issues

1. [MAJOR] REPORT §0/§8 verdict: "Positive" is reached for the CNN even though one of its four targets (log_dur) is significantly worse than random-init, and log_amp is explained by SNR alone. Excluding log_amp, the CNN passes 2 of 3 targets. The orchestrator note concedes this, but the headline table and verdict still read Positive. -> Report the verdict together with the discounted count, or state that the PREREG criterion was too weak to discriminate.

2. [MAJOR] §6 baselines: the log_amp "pass" is leakage. SNR-alone R² (0.822) exceeds the SSL R² (0.792 and 0.771), and the CIs overlap. The random-init comparison is therefore not a meaningful test for this target. -> Add a pre-specified SNR-residualised probe, or drop log_amp from the pass count.

3. [MAJOR] §6 random-init comparison: the random-init baselines are unstable and very different across architectures. Transformer random-init polarity has a seed SD of 0.084, and its mean P1 is 0.503 against 0.654 for the CNN. Each transformer "gain" is largely a weak-baseline effect. Three seeds give weak paired inference, and the bootstrap resamples blocks but not seeds. -> Report seed-level Δ ranges, and use more seeds or additional baselines (for example a trained-on-shuffled-crops or supervised-morphology encoder).

4. [MAJOR] §5 selection: selection used one validation day (366 events) with a grid span of only 0.587–0.639. The selected transformer cell (0.635) is barely ahead of the next (0.612). The CNN's "selected" cell differs from its neighbour by 0.004. The selection metric includes log_amp, which is SNR-contaminated. -> Acknowledge that the selection is noise-level, or use CV across training days.

5. [MAJOR] §7 P2 criteria: the thresholds "≤ morph8 + 0.05" and "has_dropout ≤ 0.2" are loose relative to the observed values (0.011 and 0.077). The test therefore cannot fail. The CNN has_dropout skill (0.077) equals its own permutation null (0.074), so that number is uninformative. The has_dropout null is also weirdly positive for all representations, which suggests the permutation scheme (within day) does not destroy the dependence. -> State that P2 is non-discriminative, and fix or explain the null.

6. [MAJOR] §7 run 0204 leakage: SSL training doubles the is-0204 identifiability (0.083→0.165 for the CNN, 0.025→0.113 for the transformer). All residual run skill comes from run 0204. Declaring "P2 pass / no leak" conflicts with this evidence, and it matters for a federated split by run. -> Downgrade the claim to "reduced relative to morphology but increased by training."

7. [MAJOR] §10 deviations 1–3: evaluation code was edited after results were seen, and the secondary-tier P2 was cut to 2–5 permutations. The "no criterion changed" claim rests only on the author's assertion, and git diffs or hashes of the evaluation code are not provided; only `config.py` is hashed. -> Hash `evaluate.py` and `probes.py` at each stage, or commit tagged versions.

8. [MAJOR] §9 tiers: all-SNR "Positive" verdicts are produced while SSL date/run skill is 0.14/0.20 (CNN) and 0.08/0.13 (transformer). The pass holds only because morph8 leaks more, which makes the criterion perverse. The `results_verdict.json` flags these tiers as "Positive" without the caveat. -> Mark these tiers as not evaluable, or invalid, in the JSON.

9. [MINOR] §2 holdout: the holdout is weakly held out, having been seen by C. Run 0218 is also the only run for the holdout, so the holdout is confounded with a single run and 3 days. 93 blocks with skewed sizes (max 75) give clusters of unequal weight. -> Use a weighted bootstrap or report a sensitivity check that caps block size.

10. [MINOR] §6 CIs vs text: "CNN loses duration" is attributed to time-stretch invariance without a test, for example an ablation with no stretch. This is a hypothesis, not a finding. The P1 mean across four targets in a single table also mixes R² and chance-corrected skill. -> Label the explanation as a hypothesis.

11. [MINOR] §3 crop rule (I4): the crop contains [onset, offset] for 98.4 % of events, i.e. the augmentation is aligned to the detector's segmentation. Evaluating targets derived from the same detector (m8_* on the 8 s crop) makes the probe partly circular (polarity skill of morph8 is 1.000). -> Note this circularity explicitly; it is only partly caught by the ceiling row.

12. [MINOR] P5 and §9: the claim that "SSL clusterings are more stable" is contradicted by the tables. The CNN SSL boot_ari (0.68–0.88) overlaps random-init (0.59–0.78), and the silhouette is lower at k = 3. PCA-64 stability is reported without the same multi-seed treatment. -> Soften the claim.

13. [MINOR] Reproducibility: the human pack has no labels, so the physical-proxy check was skipped. Runtime comments say P2 cost 2.97 h, whereas the log shows 10 694 s. The per-fit cost figures are inconsistent with the "54 s single-process" note. The reproduction commands omit a seed list and GPU determinism flags. -> Record the torch deterministic settings and the seeds.

14. [MINOR] `sanity_aug.py`: the noise check prints the median residual σ of 0.0073 against the max-normalised eval crop, yet the REPORT calls the noise level "realistic" without a comparison to real noise. The overfit sanity for the transformer ends at loss 1.93 (chance is 4.84), which is weak evidence that the model can memorise. -> Quantify, or soften the wording.
