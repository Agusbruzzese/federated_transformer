1. WHY, AND WHAT THIS CAN AND CANNOT SHOW
  Every study result (report 24) and every system result (reports 27-40)
  comes from the 4 375 events with SNR >= 20. The method was developed on
  those events, so the results are exploratory with respect to them. No new
  recordings exist: the dataset folder holds exactly the 4 runs (18 dates,
  "14 days") already used.
  Never used: 5 284 events with 10 <= SNR < 20, from the same days. They
  were counted and inspected descriptively during extraction (phase E), but
  NO model was ever trained or scored on them, and no protocol decision was
  based on them.
  This replication answers: do the study's conclusions hold on different,
  noisier vehicles, with everything else fixed?
  It does NOT test new days, a new season, or a new sensor. Same-day
  conditions (traffic mix, weather, noise floor) are shared with the study.

2. DESIGN (identical to the study except the data)
  - Tier: 10 <= SNR < 20, all 18 dates, the same rule as the study
    otherwise (dropout events not excluded, exactly as in the study).
  - Folds, days, server days (Feb 18 + 20), tuning day (Feb 10), noise
    pool, augmentations, model, budgets, learning rates and probes: all
    unchanged. The frozen protocol code is used unmodified. rep.install()
    fills the cache of the single data loader (m4.load) with the low-SNR
    tier before any protocol module reads data. "verify_freeze.py" runs at
    the start of the chain.
  - Learning rates are NOT re-tuned: the study's chosen values (C256
    1.5e-4; C64, F-nat, F-X+P 3e-4; S+F 1e-3) are part of the recipe
    being replicated.
  - Server pretraining is redone on the low-SNR server-day events
    (477 events; study: 434), with the study's server command.
  - Clients per fold: 10, with 141-679 events each (study: 53-434). Fold
    training events: 3 443 / 3 295 / 3 767.
  - Runs (190, commands copied verbatim from the study manifest; listed in
    rep_manifest.json):
      server 10; C256 seeds 0-9 x 3 folds; C256rep seeds 10-19 x 3;
      C64 x 30; F-nat x 30; F-X+P x 30; S+F x 30.
    SecAgg+ arm: S+F through the exact SecAgg+ simulator (dpsim, proven
    bit-identical to the real system in report 37), fold 0, seeds 0-9, on
    fl_system folders provisioned from the low-SNR tier.
  - Scoring: the frozen evaluator; untrained networks (INIT, seeds 0-9) as
    the negative control.

3. PRE-REGISTERED DECISIONS (rep.py analyze; the study's own functions)
  Procedure validity (all three required, else results are reported as
  NOT INTERPRETABLE):
    C1  C256rep vs C256 -> EQUIVALENT (the procedure can declare
        equivalence on this tier);
    C3  INIT vs C256 -> INFERIOR (it can detect a bad model);
    L1  gate calibration (m_leak rule from C256rep vs C256) -> PASS.
  Claims; "REPLICATED" means the same label as the study:
    QF  F-nat vs C256: EQUIVALENT and nuisance gate PASS (study: EQUIVALENT,
        gate PASS);
    QS  server pretraining (Holm family S+F > F-nat, S+F > F-X+P):
        HELPS (study: HELPS);
    SF  S+F vs C256: NON-INFERIOR or EQUIVALENT (study: NON-INFERIOR);
    SA  SecAgg+ vs plain S+F, fold 0, seed-paired: EQUIVALENT (study:
        EQUIVALENT, report 36).
  Margins: the study's (LOBES 0.04, POLARITY 0.02, DURATION 0.03), not
  re-derived.
  Descriptive (no claim): C64 vs C256 and F-nat vs C64 (the study's caveat),
  seed-paired sensitivity analyses, collapse check, mean scores.
  Interpretation rule: a claim that is not replicated is reported as such,
  with its label. Noisier probe labels at low SNR can lower precision and
  produce INCONCLUSIVE. That would mean "not confirmed", not "refuted",
  unless the label is INFERIOR or the opposite direction.
