## 1. Hypotheses (stated before the comparison runs)

- **H1:** `t_hours` and `dc_baseline` encode time and sensor drift, not vehicle identity. Test: leakage skill vs a shuffled-label null.
- **H2:** EMD IMF indices are not comparable across events (variable IMF count, mode mixing), and HHT features are unstable under tiny shifts or noise.
- **H3:** Vehicle information lies below a few Hz, so any feature built on > 5 Hz content encodes mains, noise or sensor state, and therefore leaks date and run.
- **H4:** Simple time-domain morphology and the raw shape are at least as informative as EMD/HHT, and more invariant.
- **H5:** KMeans pseudo-labels on these features have little structure beyond a column-permuted null.

**Pre-registered criteria.** These were fixed in `evaluate.py` before the dev/holdout runs, with PROTOCOL v1 added mid-run.

Six ranking criteria, each ranked per representation, with the mean rank as the composite:
1. **Invariance:** retrieval@1 of the source event under 4 nuisance augmentations (shift +0.1 / −0.25 / +0.5 s, added real background noise). Higher is better. Null = 1/n.
2. **Leakage, date:** HistGradientBoosting, 5-fold, balanced-accuracy *skill* = (bacc − 1/K)/(1 − 1/K). Lower is better. Nulls: majority class (0) and shuffled labels.
3. **Leakage, hour:** 6-h bin, same method. Lower is better. Caveat: traffic mix genuinely varies with hour.
4. **Silhouette excess:** silhouette at k = 5 minus that of the column-permuted null. Higher is better.
5. **Bootstrap-ARI excess:** k = 5, same null. Higher is better.
6. **Proxy:** mean of the kNN R² for log-duration and the polarity skill. Higher is better; circular for morphology (see §6).

Also reported but not ranked:
- effective dimension (participation ratio);
- run leakage;
- "sees dropout" skill;
- cluster–dropout association (NMI with permutation null, Cramér's V);
- event-vs-background skill;
- log-amplitude R²;
- scale and stretch retrieval.

**Stability rule (PROTOCOL):** the same top-2 **and** Spearman ρ ≥ 0.8. I operationalise this as composite-rank ρ ≥ 0.8 **and** median per-criterion ρ ≥ 0.8, both required. It is tested dev→holdout (Run 3) and D-events→C-events.

## 2. Data and events

- **Reader** (`io_detect.py`): `<u4` values, `<u8` Time. It was validated against A's `bsd_io.py`. Values are bit-identical on 40 random chunks, and the 29 417 paired chunks are the same set (`validate_reader.log`).
- **Deviations from A, quantified:**
  - D uses nominal fs = 2400 Hz. The true rate is 2416.6 Hz (run means 2414.3–2417.6), so durations and frequencies carry a −0.69 % scale error. The between-run spread is only ±0.07 %, far below feature noise.
  - D ignores dropouts (0.56 % of samples). A dropout compresses time by ≤ 45 ms locally, which is < 1 % of an event.
  - Both deviations are **flagged per window** (`n_gaps`, `n_missing` in `meta_flags.parquet`). 79 % of D's 10-s windows in Run 1 contain a dropout, vs 14 % in the holdout.
- **Provisional detector** (`io_detect.detect`, `scan_all.py`):
  - 20 Hz Butterworth LP (zero-phase), then decimate ×24 to 100 Hz;
  - baseline = median of 2-s blocks → 31-block running median → subtracted;
  - envelope = 0.25 s moving |r|;
  - hysteresis at 8σ / 3σ (MAD), merge gaps < 1.5 s, minimum 0.3 s;
  - window **centred on the envelope peak**, not the energy centroid, because the centroid mis-centred merged multi-vehicle events.
- **Window length:** the task suggested 2 s, but measured durations are median 3.5 s, p95 12.8 s, so a 2-s window truncates most events. **All features use an 8-s window**: 800 samples at 100 Hz, cropped from a stored 12-s window so shift augmentations are possible. Raw 10-s windows at 2400 Hz are kept for the legacy set.
- **Event counts:** a full scan (≈ 1 min for 33 GB) gave **4 797 events and 1 768 background windows**: dev 3 938 events / 1 508 background; holdout (Run 3) 859 / 260. Augmented copies were made for 700 dev + 500 holdout events.
- **Signal facts relevant to features** (`fig_psd_event_vs_bg.png`, `psd_ratio_bands_dB.csv`):
  - Event/background median PSD ratio: +33 dB at 0–1 Hz, +26 dB at 1–2 Hz, +3 dB at 2–4 Hz, and **≤ 0.6 dB for every band above 4 Hz**.
  - Mains at 50 Hz plus odd harmonics reaches about 3k counts peak-to-peak.
  - This agrees with B: big-event energy is below 2.5 Hz.
- **Two populations by amplitude** (`fig_event_gallery.png`):
  - large (5k–600k counts): bipolar or tripolar;
  - small (≈ 1–3k, near the noise floor): mostly unipolar.
  - Following B, this is an amplitude split, not proven populations. The large-only analysis is reported separately (§5.3).

## 3. Reconstruction of the legacy 70 features: fidelity

The source is `git show 6d63a85:comparison/central_pipeline.py`. Its docstring says it is "the same sliding-window EMD pipeline used by the federated clients". Column order follows `client/client.py` `FEATURE_COLS`.

| Element | Original | D reconstruction (`features.legacy66`, `legacy_add_relative`) | Fidelity |
|---|---|---|---|
| Reader | `np.frombuffer(b,'<i2')[0::2]` (low 16 bits, signed) | `legacy_read_int16` (bit-exact) | exact |
| Decimation | `vals[::24]`, no filter | same | exact |
| Window | 60 s, 30 s step, sliding | **8 s centred on each event** (the same segmentation for all representations, which the comparison requires) | deliberate deviation |
| EMD | `emd.sift.sift(max_imfs=8)`, `emd` package | PyEMD `EMD.emd(max_imf=7)` + residue, keep ≤ 8 components (`emd` is not installed; the env is frozen) | approximate |
| IA/IF | `emd.spectra.frequency_transform(...,'hilbert')` | `scipy.signal.hilbert`, phase derivative | approximate |
| dc_level, dc_range, rms (uncentred), dc_gradient = (last−first)/T, energy_mean/std/max over **IMF energies**, burst_ratio = max/mean of 1-s energies (0.5 s step), n_imfs, per-IMF 7 stats, zero-padding | as written | same formulas | exact |
| t_hours | hours since 2025-02-04 00:00 (cumulative) | same, from wall clock | exact |
| dc_relative, dc_range_rel, rms_rel, dc_baseline | lost `client/clustering.py::add_dc_relative` (per-date rolling baseline) | dc_baseline = int16 value of the 60-s running-median baseline code; dc_relative = dc_level − dc_baseline; *_rel = value − per-date median over background windows | **guessed** (source lost) |
| Input scaling | raw values (energies ~1e9–1e11) fed unscaled into `Linear` | evaluated after robust z-scoring (fairer to legacy) | favours legacy |

Two further variants isolate what drives the legacy results:

- **legacy_noconf:** legacy70 minus `t_hours`, `dc_baseline` and `dc_level`.
- **legacy_fixed_io:** the same 65 window features computed on *correct* input (24-bit, anti-aliased, 100 Hz, baseline subtracted).

Both tiers are stable, which is D's recommended training set.

## 7. Normalisation for federated, non-IID clients (D4)

(`norm_test.py`, `div_test.py`)

**Setup:** 30 simulated clients (date × 4-h slot, ≥ 30 events each, dev), mirroring the README split. Clients genuinely differ: per-client median log10 amplitude ranges 3.13–4.30 and median log10 duration 0.17–0.62.

**Per-client vs global z-scoring**

| rep | ARI(global, per-client) | log_amp R² global → per-client | log_dur R² global → per-client | client-id leakage global → per-client |
|---|---|---|---|---|
| morph | 0.31 | 0.95 → 0.83 | 0.72 → 0.62 | 0.02 → 0.73 |
| waveform | 0.70 | – | – | 0.02 → 0.68 |
| legacy70 | 0.65 | – | – | 0.97 → 0.90 |

Per-client normalisation maps the same physical event to different codes on different clients, and makes the client identifiable. Across all representations tested, KMeans partitions under global vs per-client scaling agree with ARI 0.29–0.70.

**Baseline subtracted vs divided** (B's request (2)):

- The divisor spans only 0.975–1.009 across all dev events.
- ARI between the two partitions is 0.99–1.00, and bootstrap-ARI and silhouette excess are unchanged.
- "DC-relative" division is harmless but pointless. Subtract (B agrees).

**Recommendation**

- Use **fixed physical transforms**: log10 of amplitudes, areas and energies; durations in seconds on the *true* 2416 Hz clock.
- Where robust scaling is still wanted, compute **global** statistics federatedly: aggregate per-client moments or quantile sketches once before training, then freeze them.
- For the waveform branch, use per-event max-normalisation, which needs no statistics at all, and keep `log_amp` as a scalar.
- FedProx handles the remaining non-IID drift. BatchNorm statistics should stay local (FedBN) or be replaced by LayerNorm/GroupNorm.

## 8. Contrastive design: KMeans pseudo-labels vs SimCLR pairs

**Against the legacy KMeans pseudo-labels**

- Cluster structure above the column-permuted null is modest: silhouette excess 0.08–0.25 at k = 5.
- Bootstrap-ARI excess is small or negative for several representations; the null ARI is itself 0.3–0.7.
- Clusters partly track the dropout artefact (§5.2) and, for legacy, time: legacy70 clusters come from features with 0.93–1.00 date/hour skill.
- The legacy NT-Xent treats every same-cluster pair as a positive, so it trains the encoder to reproduce these artefacts.
- The reported 96 % "downstream accuracy" predicts the same pseudo-labels, which is circular.

**Recommendation: SimCLR / NT-Xent on augmentation pairs** of the same event.

Valid augmentations and ranges (physical justification):
- time shift U(−0.5, 0.5) s: detector jitter; morph R@1 stays ≥ 0.92;
- additive *real* background window, SNR-matched: sensor noise and mains residue;
- amplitude scale U(0.8, 1.25): lane distance and gain drift. Keep `log_amp` out of the contrastive view, or accept that it varies;
- time-stretch U(0.85, 1.18): vehicle speed; invariance is desired for model recognition;
- small baseline offset or linear drift;
- mains-hum injection on the raw path only.

**Invalid:**
- sign flip: polarity encodes lane and orientation, and is 97 % predictable from shape;
- time reversal: equivalent to the opposite direction of travel;
- masking of the < 4 Hz band;
- crops that remove the main lobe;
- mixup of different events.

Optional later step: hybrid SupCon with *physically defined* weak labels such as polarity or duration tertiles. Not KMeans.

## 9. Limitations and open items

1. **The PROTOCOL stability criterion is not met** for the full ranking: composite ρ 0.77 dev→holdout; 0.47–0.53 vs C's all-SNR events. Only "morph ∈ top-2" is robust. The mean-rank composite is sensitive to small, noisy differences in the cluster criteria (ARI and silhouette excess have wide CIs, e.g. waveform ARI [0.39, 0.98]).
2. **Window length 12 s vs 21 s** with C's onset/offset mask (C's design question 1) is **not evaluated**. D used 8-s windows. Open.
3. **The learned encoder was not trained**: torch is absent from the frozen env. The waveform was evaluated as a raw Euclidean vector, which understates a CNN trained with shift augmentation. Its "proxy" and "invariance" scores are lower bounds. Open: train a 1D-CNN with SimCLR, then re-run `evaluate.py` on its embeddings.
4. D's features use the nominal 2400 Hz clock and D's provisional LP20/Butterworth front end, not B's final chain (mains regression, LP 8 Hz, 50 Hz resample_poly(25, 1208), split at dropouts). The LP-cut-off sweep (§5.2) suggests morph and waveform conclusions are insensitive to this. Porting `features.py` to B's front end is recommended before production.
5. **The legacy reconstruction** used PyEMD instead of the `emd` package, 8-s event windows instead of 60-s sliding windows, and guessed `add_dc_relative`. The central finding (int16 wrap, cumulative t_hours) does not depend on these choices.
6. **Weekend effects** are untestable on the holdout (PROTOCOL limitation). The holdout days are partial (Feb 18 from 11 h, Feb 20 until 14:40), so holdout *date* leakage is partly *hour* leakage.
7. **Only 100 events** in the IMF-level EMD audit; EEMD/CEEMDAN not run on the full set (cost).
8. **The provisional detector was used for D's own events.** C's final detector produced the same event set before and after its last revision.

**Reproducibility:** seeds are fixed (0 for bootstraps and metrics, 42 for the eval subset). Scratch arrays (LP/RAW windows, feature npz) live in the session scratchpad and are regenerated by `scan_all.py` and `compute_all.py`.

### Recommended feature list (to feed the encoder)

**Branch A: waveform.**
- 8-s window centred on the envelope peak (or C's centroid for SNR ≥ 20 events).
- Baseline subtracted; LP ≤ 8 Hz; 32 Hz; 256 samples; divided by max\|x\|.
- Input to a 1D-CNN or transformer, trained with SimCLR augmentations (§8).

**Branch B: morphology scalars.** Definitions are in `features.morph_feats`, computed on a 5 Hz-smoothed copy, with thresholds max(frac·A, k·σ_edge):

| Feature | Definition |
|---|---|
| `log_amp` | log10 max\|x\| |
| `polarity` | sign at the peak |
| `pos_frac`, `neg_frac` | max(x)/A, −min(x)/A |
| `dur10` | extent above max(0.1A, 3σ) |
| `dur50_main` | FWHM of the main lobe |
| `rise_main`, `fall_main` | 10→90 % and 90→10 % times of the main lobe |
| `asym` | relative peak position within dur10 |
| `n_lobes` | sign-alternating lobes > max(0.2A, 5σ) lasting ≥ 0.1 s |
| `first_lobe_sign` | sign of the first lobe |
| `t_pp` | time from max to min |
| `area_pos_n`, `area_neg_n` | positive and negative areas / (A·dur10) |
| `log_area_abs` | log of the total absolute area |
| `log_energy` | log of the energy |
| `t_spread` | energy-weighted time SD |
| `zc_rate` | zero crossings per second in dur10 |
| `kurt_env` | kurtosis of \|x\| |

Before production, convert time features with the true fs (×2400/fs_local).

**Excluded:** t_hours, dc_baseline, dc_level (and any absolute level), EMD/HHT features, spectral bands above 5 Hz. `has_dropout` stays metadata (mask or repair), never an input.
