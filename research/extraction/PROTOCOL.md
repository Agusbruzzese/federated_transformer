# Shared evaluation protocol (v1, 2026-09-29)

Issued mid-run after the first external audit (`AUDIT_20260929_212625.md`, issues 2–4).
It binds workstreams C and D, and the final synthesis.

## Data split (fixed before any results are seen)
- **Tuning/development:** Run 1 (Feb 4–11, includes the weekend of Feb 8–9), Run 2 (Feb 12–14) and Run 4 (Feb 24–27).
- **Holdout:** Run 3 (Feb 18–20 **11h12–14h40**), used only for final numbers, and not for choosing parameters, thresholds or feature sets.
- **Limitation:** the only weekend is in the tuning runs, so weekday/weekend effects can't be tested on the holdout. Report this as a stated limitation.
- **Excluded:** unpaired chunks, until A's integrity report says otherwise.

## Decision rules
- **C (detector):** choose on the tuning runs, then report injection recall/precision and the hand-checked precision on the holdout. The winner must beat the fixed-window baseline on the holdout, with injection F1 at SNR ≥ 6 dB, not only on the tuning runs.
- **D (features):** the ranking of representations counts only if it is **stable**. Stable means the same top-2 representations and a Spearman ρ ≥ 0.8 across criteria when recomputed (a) on holdout events and (b) on events from C's final `detector.py`. Otherwise the result is reported as inconclusive.
- **Null baselines required:**
  - Leakage (predicting time-of-day or run): compare against a majority-class baseline and a shuffled-label baseline.
  - Cluster metrics (silhouette, DB, ARI): compare against the same features with each column independently permuted.
  - Report every metric as value vs null, with a 95% bootstrap CI (≥200 resamples, fixed seed 0).
- **Reproducibility:** fix the seeds and the file lists; every number in a REPORT must be regenerated by a script in the workstream folder. Python environment: `research/requirements.lock`.
