# External audit: research/model/C1_clustering

_20261002_103059 · served by claude-sonnet-5-5 · effort medium · 20548 in / 2563 out · ~$0.067_

## Verdict
REJECT: the pre-registered design was amended three times, the last time after a failed dry run and a look at ad-hoc results. The code has bugs that affect the decision rules, and no REPORT.md, `results.json` or labels were delivered, so none of the C1 deliverables can be checked.

## Issues

1. [BLOCKER] Deliverables: only the PREREG, scripts and dry-run JSONs were provided. There is no REPORT.md, `results.json`, `cluster_labels.csv`, gallery or profiles, and `train.log` is 0 B. Nothing can be verified against any claim, and it is unclear whether the real run was executed. -> Deliver the outputs and a report with the verdict and confidence levels, or state that the run did not happen.

2. [BLOCKER] PREREG D10 / `dryrun()`: the go/no-go dry run was redesigned after D9 failed, and after an ad-hoc run of the new design had already passed. The disclosure is honest, but the gate is circular. The templates are real events, the singletons are phase-randomised real events, the SNR range is U(20, 300), and the design was tuned until it passed. The gate is therefore not a pre-registered test. D9 showed that the pipeline fails on noise-like events, and the real tier is only "SNR ≥ 20". -> Treat the dry run as a sanity check only, and report real-data conclusions with the D9 failure stated prominently.

3. [MAJOR] `dryrun()`: the "R3" arm does not test the real R3. It uses `morph_feats` on 50 Hz synthetic crops, whereas the real R3 uses the stored `m8_*` columns, which are computed on a different crop (the 402-sample one) and are NaN-filled with 0. The real R2 (SimCLR) is never dry-run. The `PASS` flag also omits any check on the overlap events (`lab == -2`), even though D9 required them. The ARI is computed on templates only, so a template point assigned to noise (-1) counts as its own class and is not penalised as a miss.

4. [MAJOR] `tightness()`: the null permutes labels among already-clustered points only. That null cannot detect that the clusters are dominated by amplitude. For R2 and R3, amplitude and duration are inputs, so the CV tests are circular (D1 acknowledges this, yet `valid()` still requires them). The null keeps the HDBSCAN cluster sizes, but the CV is computed with `amp.std()/amp.mean()`, which is unstable for small clusters. The correlation is a median over 1500 random pairs drawn with replacement. `P` was computed on raw counts, so large events dominate the Pearson comparison only mildly. Even so, R1 is clustered on the same alignment, and its V1 correlation is circular.

5. [MAJOR] `run()`, V2: the odd/even-day split is leaky for every representation. Adjacent days share traffic regimes, and the SSL embedding saw both halves. `valid()` uses `V2_oddeven` for the repro check, not the leave-one-run-out V2b that D3 added. The `ari_joint` metric ignores noise, so tiny, easily matched clusters can score high. Frac_joint is not part of the decision.

6. [MAJOR] `split_repro()` / `agree()`: for R1 on a subset, `Z[np.ix_(idx, idx)]` is passed to HDBSCAN. Transfer uses the nearest A neighbour, with no distance threshold. A B-event far from everything inherits a label, and noise handling is one-sided. `min_cluster_size` stays at 15 in both halves, even though each half has half the data, so cluster counts are not comparable.

7. [MAJOR] `run()`, V4 null: the Gaussian null with the real covariance is only run for R2 s0 and R3, and the R1 null is only one phase-randomised draw. `aligned()` on phase-randomised data may produce no clusters because log-compressed noise is far away, not because the clustering is meaningful. `valid()` uses a single draw (≤ 1 cluster), with no repeats.

8. [MAJOR] `aligned()`, mode "dist": the min over lags is taken as `sq_i + sq_j - 2·best`, where `best` is the maximum cross-correlation computed with zero-padded FFT at lags 0..shift and -shift..-1. This correctly handles the zero-padded linear shift. However, the shifted-overlap norm is not recomputed, so the value is the distance between the full x and the *truncated* shifted y plus the boundary terms. That is slightly wrong near the edges. Then `np.minimum(out, out.T)` symmetrises. It is minor, but the distance is not exactly the "Euclidean distance after shift" defined in the PREREG.

9. [MAJOR] `run()`, validity: only `R2_simclr_s0` is checked for validity, so the "valid" status of R2 depends on one seed. V1, V2 and the confounds are computed only for that seed, which makes the choice arbitrary. The condition that selects the sub-block, `name.startswith(("R1_awd_s100","R2_simclr_s0","R3_morph8","R2_simclr"))` followed by an inner `if`, is convoluted and fragile. The PCA is fit on the full data and the transfer happens afterwards, so split-half PCA leakage is not addressed. The R3 scale is already z-scored, but `fillna(0)` hides NaNs silently.

10. [MINOR] Training script `c1_train.py` monkey-patches `m4.load` and `m4.bgpool` and writes into `m5.OUT`. The background pool covers the full timeline, so this is acceptable for unsupervised clustering. No seeds are shown beyond the argument, and `rng0` is unused. `day % 2` for odd/even days breaks at month boundaries (the dataset spans two months, 31 → 1) and creates two adjacent odd days.

11. [MINOR] PREREG: `σ₀ = 100 counts` is stated as ≈ the noise σ with no cited evidence, and the 1 s shift tolerance is untested. SNR ≥ 20 events all sit on the same tier, so nothing supports the claim that clusters are vehicle-like. "Not claimed" is good, but no confidence levels are required or given per finding, which contradicts the brief.
